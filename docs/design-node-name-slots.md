# 节点名称槽位与订阅节点监控 - 设计

## 概述

把节点命名从"名字绑在节点上"翻转为"**名字是用户资产(槽位),节点是临时工**":
用户拥有的是一组名字,每个名字指向当前占用它的节点(node_key)。订阅生成时实时
解析命名链,改名/转移立即生效;节点不行了就换一个顶上,订阅输出里的名字保持不变。

配套订阅节点监控:对用户订阅实际下发的节点做 5 分钟 TCP 探活,异常走飞书告警;
宕机节点**不下架**(仍下发,用户可见"它还在,只是不可用"),并可按订阅地址开启
一个**虚拟状态节点**展示当前健康状况。

动机与痛点(现状代码事实):

- 改名只写库不碰内存池,要等下一轮机场刷新才生效(`handlers_overrides.go` 只调
  `SetNodeOverrideForUser`;覆盖层唯一生效点是 `aggregator.go` 刷新路径)。
- `NodeKey = server:port[:SNI]`,机场换 IP/端口即静默孤儿化,无任何提示。
- `standardize_names` 开启时,刷新会把手动改名无条件冲掉
  (`standardizer.go: StandardizeNodes` 不感知覆盖层),`aggregator.go:614` 注释
  声称的保护并不成立——本设计顺带修复。
- 同名无约束,订阅里可撞名。

## 命名链(下发时实时求值)

```
精选 alias(端点级,spec #84 既有)> 槽位名 > 模板标准化名 > 机场原名
```

- 槽位名是用户级统一命名层:一次起名,所有订阅地址生效。
- 精选 alias 保留原位不废弃:存量数据零迁移,单订阅临时覆盖仍有逃生口。
- 模板标准化("刷新名称"/刷新时自动重算)**跳过槽位节点**——这是对上述 bug 的
  修复:被接管名字的节点,`StandardizeNodes` 不再重算其 DisplayName。
- 生效名解析收敛为单一函数,`/sub` 生成路径与 `/nodes` 管理列表共用
  (WYSIWYG,与 `design-subscription-conditions.md` 的求值接入点哲学一致)。

## 数据模型

新表 `name_slots`(迁移 SQL 走 `internal/store/migrations/` 既有约定):

```sql
CREATE TABLE IF NOT EXISTS name_slots (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,  -- 槽位身份(issue #112):与名字解耦
  user_id    INTEGER NOT NULL,
  name       TEXT    NOT NULL,
  node_key   TEXT    NOT NULL DEFAULT '',  -- 空串 = 预建空槽(先起名后挑节点)
  created_at TIMESTAMP NOT NULL,
  updated_at TIMESTAMP NOT NULL
);
-- 字面名(不含 {index})唯一;含 {index} 模板原文可重复(issue #113)
CREATE UNIQUE INDEX IF NOT EXISTS idx_name_slots_name_literal
  ON name_slots(user_id, name) WHERE name NOT LIKE '%{index}%';
-- 双向唯一:一个节点在同一用户下只能占一个槽位
CREATE UNIQUE INDEX IF NOT EXISTS idx_name_slots_node
  ON name_slots(user_id, node_key) WHERE node_key != '';
```

- **身份按内部 ID(issue #112)**:槽位身份是自增 ID 主键,API 变更/删除按 ID
  寻址;改名不再触碰身份,为「含 {index} 模板重名放行」铺路。
- **唯一性(issue #113 修订)**:不含 {index} 的字面名在 (user_id, name) 上唯一;
  含 {index} 的模板名允许重复(同模板挂多节点或预建空槽),渲染层按
  (前缀, 槽位名, 槽位 ID) 排序从 01 自动编号——不变量从「同名撞车在模型层
  不可能」改写为「渲染结果不撞名;含 {index} 模板原文可重复」。
  node_key 双向唯一不变:一个节点在同一用户下只能占一个槽位。占冲突一律拒绝
  并返回当前占用信息,由前端弹确认后走转移(带 `force` 参数重试)。
- **多租户**:继承 `node_overrides` 的 per-user 隔离语义,超管不跨用户代管。
- `node_overrides` 的 `region`/`favorite` 不动,仍是节点级注解;`display_name`
  列弃用(见迁移节)。

## 存量迁移

启动时一次性回填(幂等):

1. `node_overrides` 中 `display_name != ''` 的行 → `name_slots`
   `(user_id, display_name, node_key)`。
2. **同名冲突**(同一用户两个节点起过同名):`updated_at` 最新者占住槽位;
   其余行**保留在 `node_overrides` 不动**,在名称管理界面"待处理冲突"区露出,
   提供"认领为槽位(改名)"/"放弃(清除覆盖)"两个动作——不替用户猜。
3. 迁移成功的行清掉 `display_name`(保留行,因 region/favorite 可能仍在用)。
4. 旧列保留不删表,回滚安全。

## 订阅生成链路改动

`server.go: filteredNodesWithPicks` 过滤链调整为:

```
内存池 -> 精选/条件/白黑名单/屏蔽(照旧)
       -> stale 剔除(照旧;槽位节点 stale 同样剔除,走空槽告警)
       -> 可用性/延迟过滤:【监控集合免疫】curated 节点跳过,其余照旧
       -> 命名链求值(alias > 槽位 > 模板 > 原名,实时)
       -> 虚拟状态节点注入(开关开启时,见下)
       -> 生成
```

- **监控集合(curated set)**:该用户全部槽位指向的 node_key ∪ 全部订阅地址
  node_picks 的 key。按用户计算,跨用户按 node_key 物理去重。
- **立即生效**:槽位写库即失效相关缓存,下一次订阅请求即用新名——不再有
  "下次刷新机场生效"的等待。前端提示文案同步修正。
- **宕机仍下发**:curated 节点跳过 `FilterAvailable`/延迟阈值,布局稳定,
  客户端自己的 url-test/fallback 组自然绕开死节点。
- `PUT /nodes/override` 保留 region 能力;`display_name` 字段拒收(400 +
  指向槽位 API 的文案),前端同步改造,无静默双写。

## 监控探针

新增订阅节点监控(建议落 `internal/nodemon`,探测原语复用 detection 的 TCP 快检):

- **总开关** `subscription_monitor_enabled`,默认 **关**(零回归);**间隔**
  `monitor_interval_sec` 默认 300(秒)。
- **监控集合**:该用户各订阅地址**实际下发节点的并集**,每轮探测前用与生成
  路径共用的过滤链现算——但**排除可用性过滤**(否则节点一旦判宕就掉出监控
  集合,永远等不到恢复探测)。stale/屏蔽节点不在集合内。
- **保险丝**:集合超过阈值(默认 200)时飞书提示一次"监控集合过大"并照常
  探测,不静默截断。
- **探测手段**:纯 TCP 连接 `server:port`(无 ICMP,免 `CAP_NET_RAW` 部署
  变更,与现有健康检查同源),超时默认 5s;连接耗时作为延迟打点落库
  (`node_monitor_samples`,供节点详情/趋势展示)。

### 告警状态机

每节点(按用户)三态 `正常 → 疑似 → 宕机`,外加恢复判定:

- 连续 **3** 次失败判宕 → 飞书告警**一次**(复用 `alert.Alerter`);
- 宕后连续 **2** 次成功判恢复 → 恢复通知一条;
- 疑似(1~2 次失败)只记录不告警;同一段故障不重复告警;
- 延迟不做阈值告警(只打点展示);
- 状态机驻内存:重启后计数清零,宕机节点需重新累计 3 次失败(可接受的
  重启后告警延迟,规格内注明)。

### 状态写回(跳变写回)

- 判宕 → 写回内存池 `Available=false`;判恢复 → 写回 `Available=true`
  (`DetectionKind=health`,与即时测试写回同机制);
- 疑似期间不写,避免节点在订阅里闪进闪出;
- 写回只影响"可用性展示与长尾过滤"——curated 节点因免疫照样下发(见上)。

### 空槽告警

刷新时槽位指向的节点被标 stale/消失:

- 该名**停发**(stale 剔除照旧),槽位保留为**空槽**;
- 飞书告警一次("节点已消失,名称 X 待指派"),同槽位未重新指派前不重复;
- 节点以同 node_key 回归(机场抽风)→ 自动恢复,无需操作;
- **绝不自动改绑**——补位永远是用户的显式动作。

## 虚拟状态节点

- `endpoints` 加列 `status_node_enabled`(默认 **关**,零回归),按订阅地址开关。
- 开启时在该地址输出**第一位**注入一个合成节点:
  - 配置为合法哑节点(指向 `127.0.0.1` 的占位配置),所有支持格式
    (Clash YAML/分享链接等)都要能生成且可被客户端正常导入;
  - 名称动态生成(订阅按请求实时生成,读最新监控状态):
    - 全正常:`📡 节点状态: 5/5 在线 · 更新于 14:35`
    - 有故障:`⚠️ 节点状态: 故障 1/5(🇭🇰 香港01)· 更新于 14:35`
      (多故障列多名;更新时间为最近一轮探测时间);
  - 该虚拟节点不参与去重/标准化/监控,仅展示。

## API 面

| 方法 | 路径 | 语义 |
|---|---|---|
| GET | `/api/slots` | 我的槽位列表(含挂载节点摘要、在线状态、空槽标记、待处理迁移冲突) |
| POST | `/api/slots` | 新建槽位 `{name, node_key?}`;空 key = 预建空槽 |
| PUT | `/api/slots/{name}` | 改名/指派/转移 `{new_name?, node_key?, force?}`;冲突返 409 + 占用信息,前端确认后带 `force` 重试 |
| DELETE | `/api/slots/{name}` | 删除槽位(节点回退模板/原名) |
| PUT | `/api/nodes/override` | 仅 region;`display_name` 拒收(400) |

## 前端

节点管理页内消化 + 一个综合管理区,不新增独立页面:

- **名称槽位管理区**(节点管理页内页签/区块):全部槽位列表——名字、挂载
  节点、地区、在线状态、最近探测;支持预建空槽、改名、删除;**空槽亮红灯**,
  一键"指派节点"(候选按同地区+可用过滤);迁移冲突待办区同处展示。
- **节点行**:名称列显示生效名(槽位名加小标记,一眼可辨"这个名是我管的");
  原"编辑覆盖"对话框改为"指派名称":可选已有空槽名(转移场景)或输入新名,
  地区覆盖保留在原对话框。
- **告警横幅**:宕机/空槽除飞书外,节点管理页顶部横幅同步提示(push + pull
  不重复打扰:横幅只是常显状态,不弹窗)。
- 保存提示文案从"下次生成订阅生效"改为"已生效"(实时语义)。

## 兼容与零回归

- 监控总开关默认关、虚拟状态节点默认关:存量实例行为不变。
- 无槽位用户:命名链退化为现状(alias > 模板 > 原名)。
- 标准化跳过槽位节点属于 bug 修复,在变更日志中明示。
- 迁移幂等可重入;旧 `display_name` 列保留,回滚安全。

## 验收标准

1. 改槽位名后**下一次订阅请求**即用新名,无需等机场刷新。
2. 同一名字指派给另一节点(带确认),订阅输出名字不变、指向新节点。
3. 槽位节点 TCP 连续 3 次失败:飞书一条告警 + 订阅仍下发该节点 + 虚拟节点
   文案变故障态;连续 2 次成功:恢复通知 + 文案恢复。
4. 槽位节点 stale:订阅停发该名 + 空槽告警 + 界面亮灯;同 key 回归自动恢复。
5. `standardize_names` 开启时,机场刷新不再冲掉槽位名;非槽位节点标准化
   照旧。
6. 存量 display_name 覆盖自动迁移;同名冲突进入待处理区,不丢数据。
7. 监控/虚拟节点开关默认关时,全量输出与升级前完全一致。
