# ADR 0015: 节点深度体检的能力边界与组织方式

## 状态
**已采纳** — 2026-07

## 背景

社区 `bench.sh` 式脚本常把"跑分"堆在一起:宿主机 CPU/内存/磁盘 I/O、单点测速、Ookla speedtest。ProxyHub 要给节点做"体检",必须先回答:哪些指标真正反映**节点质量**,哪些只是噪声。

评估结论:

- **宿主机系统信息 / 磁盘 I/O**:测的是运行 ProxyHub 的本机,与被测节点的链路质量无关。纳入只会误导。
- **Ookla speedtest 二进制**:闭源、按 CPU 架构分发、且其测速流量不走代理隧道 —— 测不到"经由该节点"的真实速率。不可行。
- **多地域测速**:用纯 HTTP 下载切片,流量经节点出口到多个大洲的探测点,能刻画节点的地理带宽画像。**这是 bench.sh 思路里唯一值得吸收的部分。**

同时要决定"横向比"与"纵向挖"如何分工:解锁类结果(能不能看 Netflix / 用不用得了 OpenAI)适合全节点横向对比;稳定性与多地域测速开销大、耗时长,只适合对单节点深挖。

## 决策

1. **体检只做三件事**:稳定性采样、多地域测速、流媒体/AI 解锁判定。**明确不做**宿主机系统信息、磁盘 I/O、上行测速、Ookla 集成。
2. **按"横向 vs 纵向"分流量入口**:
   - **解锁判定**进批量检测(`detection`),可对全部/筛选/选中节点横向跑,结果落 `node_health`,在节点列表/抽屉横向展示。
   - **稳定性 + 多地域测速**只作为**单节点深度体检**(`POST /api/nodes/exam/stream`)纵向深挖,不进批量。
3. **测速探测点用纯 HTTP、无二进制依赖**:8 个 Linode DC 的 `100MB-<dc>.bin` 切片,与带宽测试回退点一致(见 [design-node-exam](../design-node-exam.md))。

## 后果

### 正面
- 体检指标全部"经由节点"测得,无宿主机噪声,跨机器可比。
- 无外部二进制/闭源依赖,单二进制形态不被破坏(对齐 [ADR 0003](0003-sqlite-single-binary-reverse-proxy.md))。
- 横向/纵向分工清晰:批量检测保持轻快(全节点可跑),重活收进单节点体检。

### 负面
- 无宿主机跑分,想对比"服务器硬件档次"的用户拿不到数据(非本系统目标,不补)。
- 单节点体检耗时(~80s),不适合大批量;想批量看稳定性需后续迭代(后台巡检,见边界)。

## 边界(明确不做,留待后续评估)
- 后台定时巡检、稳定性历史趋势曲线。
- 多地域**上行**测速。
- 宿主机系统信息 / 磁盘 I/O / Ookla。
