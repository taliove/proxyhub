# ADR 0033: 订阅地址拉取防护与整站 IP 黑名单

## 状态

已接受

## 上下文

订阅地址(/sub)是全站唯一公开无鉴权入口:随机 path + token,公开但不可枚举(CONTEXT.md)。此前对它没有任何主动防护——无限频、无来源过滤,`pull_logs` 只在成功下发后留痕,被拦请求(错 token、禁用)完全不可见;登录侧的 IP2Ban 体系(ADR 0010)按设计不覆盖 /sub。威胁面:URL 泄露被蹭用、脚本刷量耗资源、扫描探测、出事无法溯源。

关键权衡:

1. **防护判定的位置**:在最外层中间件拦(简单)还是在 token 验证之后拦(信息多)?前者会把防护响应发给所有探测者,泄露"这里有东西";后者只对持有效 token 的请求给真实响应码。
2. **观察 vs 直接拦截(地域过滤)**:GeoIP 对移动网络的判定有系统性偏差(蜂窝出口常落网关省),直接拦截有自锁风险。
3. **自动黑名单的作用域**:限频顶格者是否直接全站拒止?过激进(NAT 误伤面)与过温和(扫描者仍可碰管理面)之间取折中。
4. **管理面白名单**:讨论后否决——自锁风险大于收益,且 Site Path 隐藏 + loopback 监听 + Caddy 层白名单(SECURITY.md §5.2 示例)已构成三道防线,应用内白名单是重复建设。记录在此备查,不再复议。

## 决策

1. **判定顺序铁律**:所有拉取防护判定在 path + token 验证通过**之后**执行。无效 token 永远只得统一 404(与 path 不存在逐字节一致);429/403 只发给持有效 token 的请求。守卫链(黑名单 → 地域 → 限频)由骨架统一执行:每个守卫产出 allow/observe/block 三种判定,**留痕与响应由骨架代理**,守卫不可能忘记留痕或重复应答。
2. **异常拉取全量留痕**:`pull_logs` 加 `status`(ok / rate_limited / geo_blocked / geo_would_block / blacklisted / disabled / bad_token),所有到达 handler 的请求(含被拦)都记录;503/500 等服务端态不留(无客户端可归因的状态值)。**聚合统计口径限定 `status='ok'`**——总拉取数/独立 IP/趋势只反映真实客户端拉取(延续 ADR 0028 口径),扫描探测不灌爆统计;明细保留全部状态。
3. **拉取限频**:IP × 订阅地址内存滑动窗口,默认 60 次/小时(超管设置,0=关闭),超限回 429 + Retry-After。内存实现,重启清零(瞬态语义);阈值读设置有短 TTL 缓存(不在被拒路径上打 DB);键数有上限,超限采样淘汰(洪峰下不无界增长,也不在锁内全量排序)。
4. **统一规则表 `ip_access_rules`**:(IP/CIDR, scope=global|sub, source=manual|auto, expires_at 可空=永久)。`UNIQUE(ip_or_cidr, scope)` 使重复封禁为滑动 upsert。精确 + CIDR 匹配,内存全量缓存写时失效;**loopback 任何规则下不命中**(SSH 隧道是逃生门)。
5. **拉取黑名单**:scope=sub,命中回 403。自动升级链:同一 IP 1 小时内被限频达 10 次(超管可配)→ 自动写 source=auto、默认 24h 规则;计数跨订阅地址聚合(分散刷多个地址不免疫),查询走专用索引(被拒路径不放任全表扫描);loopback 不进入升级链。**自动条目默认 sub,超管可手动升级为 global**——自动不直接全站拒止(NAT 误伤面),人工判断后才扩大。
6. **地域白名单**:订阅地址级三档:关闭(默认)/ 观察(判定不拦,记 geo_would_block)/ 拦截(未命中 403,记 geo_blocked)。**空列表 = 该维度不判**(收窄是显式动作);**未知位置保守判未命中**(查询失败/私网/无数据),防"库不覆盖即绕过"。拦截档回 403 而非 404:持有效 token 者的误配需要可调试,且响应体不含国家列表不泄露配置。**省级维度数据门控**:当前内嵌库为 Country 级(省级数据为零),省份配置永不命中——UI 折叠警告,代码已按真实记录形态接线,换 City 级库即生效;有测试在数据获得省级字段时大声报醒。
7. **整站 IP 黑名单**:scope=global,由挂在 Site Path 中间件之后、路由分发之前的中间件执行,命中统一 404(与 Site Path 未命中同一调用,逐字节无区分)。store 查询失败 fail-open(黑名单是纵深防御,DB 抖动不该锁死整站)。

## 理由

- 判定顺序铁律是全部设计的支点:防护响应码(429/403)本身也是信息,只给已证明持有 token 的人;探测者永远面对一堵无差别的 404 墙。
- 骨架代理留痕与响应,把"每个守卫都要记得写 status"从纪律变成结构——后续新守卫只需做判定。
- 黑名单排链首:已被禁的来源不该消耗滑窗配额,也不该再触发升级链重复计数;查询走内存规则缓存,排第一零成本。
- 观察档是地域类过滤的标准安全姿势:用 `geo_would_block` 留痕验证 GeoIP 对自己设备的判定准确率,确认无误伤再升拦截——这与"未知位置保守未命中"配对,前者给验证手段,后者封绕过通道。
- 403(持 token 者的拉取拦截)与 404(无差别墙)的分工:对外不泄露,对内可调试。

## 后果

- `pull_logs` 增长加速(被拦也留痕),清理策略单独立项(issue 0048,90 天 retention 对齐 audit_logs)。
- 限频/黑名单/地域配置全部超管设置化,普通用户不可调(防自我削弱)。
- 内存态(滑窗、规则缓存)重启即失效:限频计数清零可接受(瞬态);规则在库,缓存自然回暖。
- 整站黑名单对 /sub 有效 token 持有者也是 404(不是 403):global 语义就是"这站不存在",与拉取层的 403 刻意不同。
- 省份维度在换 City 级 GeoIP 库前不可用(数据门控),届时只需更新库文件并移除 UI 警告。
