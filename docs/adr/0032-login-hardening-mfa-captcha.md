# ADR 0032: 登录加固:渐进式验证码与强制 TOTP MFA

## 状态

已接受

## 上下文

登录面长期只有单段式用户名+密码,防护仅 IP2Ban 阈值封禁与蜜罐用户名(ADR 0010)。两个结构性盲区:① 分布式慢速爆破(每 IP 低于封禁阈值)从单 IP 视角不可见;② 凭证泄露(撞库/钓鱼)即账号沦陷,无第二因素。立项基调是预防性加固,不以已观察到攻击为前提。

关键权衡:

1. **验证码常驻 vs 渐进**:常驻对管理员日常登录是长期摩擦;本项目多数部署只有管理员自己登录,爆破面小但存在。
2. **自托管 vs 第三方人机校验**(Turnstile/reCAPTCHA):第三方强度更高,但要求外网可达、加载第三方 JS、向第三方暴露登录面信号——与单二进制+离线自洽基因(内嵌 GeoIP 同理)及"公开但不可枚举"哲学相悖。
3. **TOTP 密钥落库**:加密需密钥管理设施,与单二进制本地运行相悖;密钥与 DB 同机同权限时加密只是混淆。
4. **受信 IP 免验 vs 一律强制**:免验让 MFA 从"每天 N 次"降为"新环境一次",是强制政策可持续的前提;代价是免验期间单因素即可登录。

## 决策

1. **渐进式自托管图形验证码**:同一 IP 登录失败达 `captcha_trigger_threshold` 次(超管设置,默认 1,0=常驻)后必须过验证码;判定依据 `banned_ips.fail_count`(NULL 视为 0)。6 位字母数字(显式剔除易混淆字符 0/O/1/I/l),噪点+干扰线,TTL 5 分钟,**一次性:提交即作废,对错都算**。验证码错误计入 `fail_count`(与密码错误同阈值同封禁)——这让爆破验证码在数学上不可能(约 9 亿空间 × 每 IP 仅 threshold 次尝试),图形只需挡 OCR。前端由 401 响应体 `captcha_required` 驱动,无独立探测接口(避免攻击者侦察点)。签发端点 per-IP 节流 30/min。
2. **TOTP 全员强制**(超管+普通用户):复刻 `requirePasswordChanged` 模式做 `requireMFAEnrolled`,未绑定账号登录后只能进绑定页。密钥明文落库,与库中既有凭证(机场 token、节点密码)同一防线;SECURITY.md 显式声明 data.db 凭证等级。
3. **两段式登录握手**:密码通过但需 MFA 时发 `mfa_pending`(内存、TTL 5 分钟、绑定签发 IP、5 次验证失败销毁、成功即销毁、Peek/Consume 两步分离),第二段验 TOTP 或恢复码换正式会话。判定顺序铁律:IsBanned → 蜜罐 → 验证码(先于验密,使爆破够不到 bcrypt)→ 验密码 → **绑定检查先于受信判定**(修正:受信授权不能豁免绑定义务)→ 受信直通 / 发 pending。
4. **受信 IP 模型**:按用户隔离,初始为空,仅显式决策(MFA 成功页勾选"信任 30 天"或采纳推荐);30 天过期,受信登录超 24h 才续期;可撤销,超管可清空。推荐引擎只统计带 `mfa=` 标记的真实二段登录(30 天 ≥3 次),`mfa_skipped=trusted_ip` 刻意不匹配 `mfa=` 格式防自喂;`auto_trust_ip`(租户级,默认关)开启后达阈值自动信任。**不做静默自动信任**。loopback 不自动受信(反代后所有请求都看似 127.0.0.1,常驻授权会豁免所有用户),可显式信任。
5. **三层恢复通道**:10 个一次性恢复码(SHA-256 hash 落库,绑定时强制确认已保存)→ 超管 Web 重置任意用户 → loopback CLI `reset-mfa` 重置超管(proxyhubctl 交互确认)。能上机器 = 最高权限,CLI 不认证任何东西,只防手滑。
6. **loopback 豁免边界**:豁免封禁/蜜罐(既有)/验证码;**不豁免 MFA**。

## 理由

- 验证码错误计入封禁计数是整个设计的强度支点:它让"软拦截"有了硬后盾,图形复杂度得以保持人可用。
- 一次性"对错都算"封死同图重试(否则同一 challenge 可无限提交,节流形同虚设);前端失败后自动换新图,typo 体验无损。
- `mfa_pending` 绑定 IP + 失败预算 + 短 TTL,使泄露的握手凭证不可移植、不可爆破;Peek/Consume 分离是为保住失败预算(Consume 先销毁会让预算变死代码)。
- 三段分流中"未绑定发会话带标记"而非拒登,与首登改密同一心智:进得来,但哪儿也去不了。
- 受信 IP 的每个参数(30 天、显式、可撤、推荐不自喂)都在给"免验"这个风险开口上保险。

## 后果

- `POST /api/login/mfa` 不做 IsBanned 检查(有意):pending 已绑定用户+IP+TTL+预算,其持有者已证明密码;封禁拦截新握手签发,在途握手可完成。钉在 login_e2e_test.go。
- 内存态(验证码挑战、mfa_pending、会话)重启即失效:文档已声明,用户感知为"重登一次"。
- 审计新增 `captcha_failure`/`mfa_enrolled`/`mfa_failure`/`mfa_reset` 及受信 IP 系列事件;`login_success` 的 detail 带 mfa 标记。
- 恢复码重新生成需二次确认(TOTP 或恢复码),防"重新生成未保存 + 旧码已废"自锁。
- data.db 敏感度升级(含 TOTP 密钥明文):备份按凭证等级对待。
