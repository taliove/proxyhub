# ADR 0042: 定时刷新默认关闭(反转 ADR 0004 的默认开)

## 状态

accepted

## 日期

2026-08-05

## 上下文

ADR 0004 引入"定时刷新"开关时定默认**开**,理由是保持现状。生产一年期观测推翻了该前提:

- **403 是机场订阅的常态**,不是故障。相当比例的机场订阅地址封锁服务器出口(UA/IP 黑名单、只允许浏览器或客户端 App 拉取),定时拉取对这类机场永远失败。默认开意味着每个部署每 15 分钟制造一轮必然失败的出站请求和一条 `aggregation aborted: all airports failed` ERROR 日志——纯噪音。
- **节点更新已有完整的事件驱动替代**:手动刷新(全量/单机场)、粘贴导入、文件导入、机场创建后的引导,全部不依赖定时器。
- **ADR 0004 的主要后果已消解**:当年"关闭定时 → 重启后池空 → 订阅 503"的代价,已被后来的节点池快照持久化(启动 `restoreNodePool` 回填)化解——重启后池从快照恢复,不再依赖启动刷新。
- 健康检查与定时拉取耦合在同一流水线:默认开时,全挂中止发生在健康检查之前,池健康数据照样冻结(见"聚合全挂仍跑健康检查"的配套改动)——定时器开着也并没有换来健康数据新鲜。

## 决策

`scheduled_refresh_enabled` 的默认从开反转为**关**,开关本身保留(全局 + 租户级,设置 UI 不变):

- 未显式设置(含所有未碰过该开关的既有实例)→ 不做启动刷新与周期刷新。
- 语义从"显式 false 才关"(fail-open)反转为"显式 true 才开"(fail-closed):设置读取失败按关处理——宁可不刷,也不默认外打机场 URL。
- 手动刷新、单机场刷新、粘贴/文件导入不受开关影响,与 ADR 0004 一致。

## 后果

- 升级后,未开过该开关的实例不再定时外打机场 URL;需要定时更新的用户在系统设置里显式打开即可(语义对老用户可见、可回退)。
- 池健康数据的来源变为:全量刷新(手动或开了开关的定时)+ 聚合全挂时对保留池的健康检查续命 + 手动检测动作。
- 订阅可用性不再系于定时器:快照恢复兜底重启,事件驱动兜底更新。

## 相关决策

- ADR 0004(机场刷新可关闭,纯手动触发):本 ADR 只反转其默认值,开关机制与"手动刷新不受影响"语义不变。
- ADR 0003(只持久化配置与统计):节点池快照持久化是其后的演进,是本反转成立的前提。
