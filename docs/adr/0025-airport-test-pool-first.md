# ADR 0025: 机场测试 — 诊断解耦与池优先策略

## 状态
**已采纳** — 2026-07-21

## 背景

ADR 0024 实现的机场测试流水线(诊断→抽样检活→评分)在实际使用中暴露一个阻塞问题:部分机场的订阅 URL 需在其面板手动开权限后才可用,平时处于关闭状态。当 URL 不可达时,测试直接 failed——即使节点池中已存在该机场之前同步的节点,这些节点完全可以用于测试该机场的当前质量。

维护者决策:**池内优先**。订阅 URL 不可达时,只要池内有该机场的已同步节点,测试就应继续执行,评分基于池内节点的真实健康状态。URL 拉取诊断结果仅作参考信息,不阻断测试流程。

## 决策

### 1. 诊断非阻断,池优先分支

新流水线 = 拉取诊断(非阻断)→ 池优先分支 → 抽样检活 → 评分。

**分支 A:池内有该机场节点**(按 `nodes.source` 匹配当前池,排除 stale)
- **URL 可达**(HTTP 2xx):用池内节点测试,诊断结果作信息展示。
- **URL 不可达**(HTTP 非 2xx 或 fetch 失败):仍用池内节点测试,不阻断。诊断区标记「订阅 URL 当前不可达」;评分中「拉取健康」维度记 N/A,权重重归一(见 §2)。

**分支 B:池内无该机场节点**
- **URL 可达**:复用诊断阶段已拉到的订阅内容做单机场 upsert 合并入池(与全局刷新同口径:解析 → 地区识别 → MergePool carry-forward 检测状态 → 注入池),然后照常抽样检活+评分。
- **URL 不可达**:run failed,error_message 明确(「订阅 URL 不可达且池内无已同步节点」)。

这是对 ADR 0024「被拒绝的替代方案:单机场聚合写回」的限定反转。理由:URL 不常开是现实约束,池内节点是真实信号,丢弃它不符合测试目的(评估机场当前质量)。限定为「池空时才 upsert」避免测试变成刷新的副作用(ADR 0024 的原拒绝理由)——正常运行的机场,全局刷新已保证池最新;测试只在池空(极端情况)时补救性入池。

### 2. 拉取健康 N/A 时权重重归一

ADR 0024 原始权重:可用率 50% + 延迟 30% + 拉取健康 10% + 地区覆盖 10%。

URL 不可达时,「拉取健康」维度无意义(HTTP 非 2xx),标记 N/A。为保证总分仍为 0-100,将其 10% 权重按原比例重分配到其余三维度:

- 原比例 availability:latency:region = 50:30:10 = 5:3:1
- 重归一后:可用率 5/9×100 ≈ 55.56%,延迟 3/9×100 ≈ 33.33%,地区覆盖 1/9×100 ≈ 11.11%

实现:CalculateScore 内部按 httpStatus 判断,非 2xx 时自动切换权重,调用方无感知。

### 3. 单机场 upsert 复用全局刷新逻辑

池空+URL 通时的 upsert 路径,最大化复用既有纯函数:

- **地区识别**:复用 `geoip.LookupCountry`(离线 GeoIP,非阻塞)
- **合并**:复用 `subscription.MergePool`(carry-forward 检测状态)
- **写回**:调用 `store.SaveNodePool`

接缝:`PoolOperations` 接口(LoadPoolBySource / UpsertAirportNodes),生产实现 `StorePoolAdapter` 封装上述逻辑,测试实现 `MockPoolOperations` 验证分支。

注意:单机场 upsert 只合并该机场节点(按 source 过滤旧池),其他机场节点原样保留,避免误触碰无关节点。

### 4. 前端对话框诊断区三态

- **成功**(HTTP 2xx):现有展示(绿色 tag,节点数/协议分布/耗时)
- **不可达**(HTTP 非 2xx,但池有节点):warning tag「订阅 URL 当前不可达,使用池内已同步节点测试」,不阻断,继续显示后续阶段(检活/评分)
- **失败**(HTTP 非 2xx 且池空):error tag,run failed,error_message,后续阶段不显示

## 后果

- **诊断不阻断**:URL 临时不可达(机场面板权限未开/CDN 抖动)不再让测试失败,提高可用性。
- **权重重归一**:URL 不通时评分仍为 0-100,维度间比例保持一致(5:3:1),横向对比仍有效。但「拉取健康」信息缺失,无法评估机场订阅本身的健康度(只能评估已入池节点质量)。
- **单机场 upsert**:限定为池空场景,避免测试成为刷新副作用;但引入新写路径,与全局刷新并行,需保证逻辑一致性(通过复用 MergePool 保证)。
- **复杂度**:流水线分支增加,orchestrator.RunTest 从单线性流程变为条件分支(池有/池空 × URL 通/URL 不通 = 4 条路径),测试覆盖面增大。

## 实现细节

- `Orchestrator.RunTest` 新增 `airportName` 参数,用于 `PoolOperations.LoadPoolBySource` 匹配池内节点
- `CalculateScore` 自动检测 httpStatus,非 2xx 时内部切换权重,透明重归一
- Handler 调整:诊断阶段 fetch 失败不再返回 500,记录 HTTPStatus=0 后继续创建 run,异步 RunTest 根据池状态决定 pass/fail
- 前端:`AirportTestDialog.vue` 诊断区按 HTTPStatus + run.status 组合判断三态展示
