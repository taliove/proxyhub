# ADR 0017: 体检编排 - 三段串行与稳定性独占

## 状态
**已采纳** — 2026-07

## 背景

单节点深度体检有三段:稳定性采样(30s × 1Hz 打 `generate_204`)、多地域测速(8 区下载切片)、解锁判定(6 目标)。三段共用一个节点代理会话(`internal/detection/mihomo.go`)。

直觉上"并行跑更快",但这里并行会污染测量:

- **稳定性**测的是延迟序列的抖动/丢包/长尾。若同时有多地域测速在下大文件,带宽被抢占,延迟序列被人为拉高、抖动失真 —— 稳定性分不再反映节点真实空载表现。
- **多地域测速**各区互相抢带宽,测出的下行速率也会互相压低,失去"各区独立画像"的意义。
- **解锁判定**都是小请求,彼此无带宽竞争。

## 决策

三段**严格串行**,顺序固定,总预算 ~80s,SSE 分段推送进度:

```
[稳定性采样 30s 独占] -> [多地域 8 区串行 ~40s] -> [解锁 6 目标并行 ~10s]
```

- **稳定性必须独占**:采样期间不得有任何其他段并发占用会话带宽。
- **多地域各区串行**:一次只测一个 DC,避免区间互抢。
- **解锁内部并行**:小请求无带宽竞争,并行以省时。

编排器按段驱动,SSE 逐段推 `sample` / `region` / `unlock_result` / `section_done` / `done` 事件;前端按段渲染。

## 后果

### 正面
- 稳定性分与各区速率反映节点**空载真实表现**,不被同批测量互相干扰,跨节点/跨次可比。
- 分段 SSE 让 ~80s 的长任务有持续进度反馈,不是一个黑盒等待。

### 负面
- 串行使总时长固定在 ~80s 量级,无法靠并行压缩 —— 这是测量正确性的必要代价,不是可优化项。**后续若有人想"并行提速",必须先理解本 ADR:并行会破坏稳定性/测速的测量语义。**
