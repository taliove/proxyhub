# ADR 0041: 地区识别三层兜底链(名称规则 > emoji 反解 > GeoIP)

## 状态

accepted

## 日期

2026-08-03

## 上下文

生产观测(issue #37):341 个节点中 177 个地区为 Unknown(马尔代夫/不丹/文莱/关岛等)。这些节点名称里国旗 emoji、中文名、ISO 后缀齐全,但规则表(`internal/store/region.go`,19 个预置地区)未覆盖,`Recognize()` 无匹配即返回 "Unknown"。后果是按地区筛选选不到、分区占位符覆盖不全、管理页地区列大片「未知」。

更根本的问题是现状存在三条互相覆盖的识别路径,口径互不统一:

1. **fetcher 解析期 `extractRegion`**(`internal/subscription/fetcher.go`):使用较宽的匹配规则在拉取解析时填充 Region,未命中时返回 "Unknown" 而非空串。
2. **aggregator 全量刷新 `recognizeRegions`**(`internal/aggregator/aggregator.go`):用 18 地区窄表对整池**无条件重算覆盖**——解析期宽表已识别出的地区被窄表重算回 "Unknown"。这条路径不是兜底,而是 Unknown 的主动制造者:它把已经正确的识别结果系统性洗没。
3. **poolops GeoIP 兜底**(`internal/poolops/poolops.go`):`node.Region == ""` 的 guard 恒为 false(因路径 1 的 fallback 返回 "Unknown" 而非 ""),GeoIP 分支是死代码,从未生效;且机场节点 Server 全是域名,未先做 DNS 解析,即便 guard 放开也会失败。自建节点路径(`internal/server/nodes.go`)做对了(先 DNS 再 GeoIP),但正确做法没有复用到机场入池。

与此同时,`internal/geoip` 已内嵌 dbip-country.mmdb,`LookupCountry(ip)` 离线可用;直连出口的 DoH 解析器(防 TUN fake-ip 劫持,带 TTL 缓存)也已存在。补齐兜底所需的零件都在,缺的是统一的识别链与统一的入口。

## 决策

1. **统一三层识别链,前层命中即停**:

   - **L1 名称规则**:现有规则表(19 个预置地区),优先级最高——机场标注的是出口地区,语义最准。规则表内容不变。
   - **L2 国旗 emoji 反解**:扫描节点名中的区域指示符对(U+1F1E6..U+1F1FF x2),算法反解 ISO 3166-1 alpha-2 代码(`RegionEmoji` 正向算法可逆,零网络、零枚举表)。节点名含多面国旗(如 🇺🇸🇯🇵 中继标注)时**确定性取第一个**(从左到右扫描),与入口标注习惯一致;非法/单只指示符忽略。
   - **L3 GeoIP 兜底**:前两层未命中时,DNS 解析 Server(复用直连出口/DoH 机制,防 TUN fake-ip)→ `LookupCountry` → server 维度持久缓存(带 TTL,含短 TTL 负缓存),避免每轮刷新重复解析。Server 本身是 IP 时跳过 DNS 直接查库。

2. **语义原则:出口语义在前,落地语义在后**。L1/L2 识别的是**出口语义**——机场在节点名里标注的是用户感知到的出口地区。L3 GeoIP 量的是**落地语义**——服务器机房位置,中转节点的落地可能 != 出口。因此 GeoIP 只能放最后做兜底,绝不允许覆盖前两层的标注结果。

3. **识别入口统一**:全量刷新(aggregator)、单机场 upsert、手动导入、机场测试池空补救全部经 poolops/aggregator 走同一个三层识别函数,同输入同结果。两条时序不变量保持不动:识别在注入自建节点之前(SELF 标记不被覆盖)、用户 region 覆盖层在识别之后最终生效。

4. **识别层 best-effort 静默降级**:任何一层失败(DNS 超时、DoH 不可用、私网 IP、mmdb 未命中)都静默降级到下一层或保留 "Unknown",只记日志。这与检测链路的严格模式(直连出口绑定失败即报错)是**有意不同**的纪律:识别失败不阻断入池与下发,检测失败必须显式暴露。DoH seam 返回错误,由识别层决定降级,不复用检测的报错路径。

5. **不迁移存量数据**:存量 Unknown 节点不写一次性迁移,随下轮入池/刷新经统一识别链自动翻正。

## 后果

正面:

- 小众地区节点(规则表未覆盖但名称带国旗)经 L2 零成本翻正;名称无线索的经 L3 GeoIP 兜底。生产 177 个 Unknown 中的绝大多数随下轮刷新收敛。
- 三条路径收敛为一条链,全量刷新与单机场 upsert/手动导入口径统一,"同输入同结果"成为可断言的测试义务。
- 窄表无条件覆盖宽表的覆盖事故根除:识别链前层命中即停,不存在后层洗没前层结果的通道。

外部可见的口径变化(必须明示):

1. **`/sub/{path}` 下发集可能变大**:地区白名单非空的订阅,原 Unknown 节点翻正后可能新命中白名单而开始下发。这是修复语义——这些节点本就是白名单地区的节点,此前是因识别失败被错误排除;但客户端会观察到下发节点变多,属本决策的目标行为。
2. **名称标准化的 region 段可能显示陌生代码**:`internal/subscription` 的 `RegionInfoMap` 只含规则表 18 个地区的元数据;L2/L3 产出的新 ISO 码(如 MV)不在表中,标准化名称的 region 段显示为代码本身(如 "MV")。可接受:代码本身是标准 ISO 码,语义明确;后续可按需向 RegionInfoMap 补录显示名。

关联与边界:

- **ADR 0021(节点地区真相链 - 出网优先于 GeoIP)**:方向一致,不冲突。本决策管**入池时的初始识别**(名称规则 > emoji > GeoIP),ADR 0021 管**体检后的真相回写**(egress 总是覆盖)。体检拿到真实出口国家码后仍是最终纠正手段——包括纠正 GeoIP 兜底猜错的值。三层链产出的是"尽可能好的初值",egress 回写是"地面真相的终裁"。
- **ADR 0018(NodeKey Upsert 与 carry-forward)**:地区识别仍是每轮刷新重算的字段,carry-forward 不携带 region 跨轮(与检测状态的 carry-forward 边界不同);三层链只是让每轮重算的结果更准。
- **ADR 0011(地区识别与分组系统)**:本 ADR 是其细化——把单层规则表扩展为三层链,不改"识别结果存 `nodes.region`、供订阅时过滤与分组"的既有定位。
- **extractRegion 的处置**:统一识别链接管后,fetcher 解析期的 `extractRegion` 成为冗余的第三条路径,必须收缩(解析期只跑无 ctx 可做的 L1+L2)或删除(Region 由识别器全权填充),**不得原样保留**——否则解析期宽表与识别器继续互相覆盖,本决策要消灭的事故原地复活。具体收缩还是删除由实现层定。
- **poolops GeoIP 死代码消除**:`node.Region == ""` 恒假 guard 随统一接线删除,GeoIP 兜底第一次真正生效。

性能约束:L3 引入 DNS + GeoIP,若缓存/并发/超时失守,全量刷新会从秒级退化到分钟级(177+ 节点逐个 DNS)。因此 server 维度持久缓存(TTL + 负缓存)与有界并发是接线全量刷新的**前置条件**,不是可选项;实机验证必须看刷新耗时。

被放弃的备选:

- **GeoIP 前置或并入 L1**:GeoIP 量的是落地语义,中转节点落地 != 出口,前置会用机房位置覆盖机场标注的出口语义,方向性错误(实测案例见 ADR 0021)。否决。
- **在线 geo 查询(ip-api.com 等)**:引入外网依赖与隐私外泄面,内嵌 mmdb 已够用。否决。
- **存量 Unknown 一次性迁移**:识别链上线后随下轮刷新自然翻正,迁移脚本是无谓的不可逆动作。否决。
- **多国旗取最后一个**:中继标注习惯入口在前,且"取第一个"实现与测试都更简单;无证据表明取最后一个更准。否决。
