# ADR 0031: 模板编辑器升级:CodeMirror、校验门控自动保存与模板版本

## 状态

已接受

## 上下文

模板库(ADR 0030)落地后,编辑页暴露三个问题:Monaco 是前端最大依赖(页面 chunk ~2.3MB)却只用到了基础高亮编辑能力,重型依赖轻用;显式保存按钮易被忘记,且保存即生效的语义下没有后悔药;历史上改坏配置无法回退(实践中踩过 YAML 语法坑)。

两个关键权衡:

1. **自动保存 vs 落库即生效**:模板改动保存后立刻对订阅方生效(ADR 0006 起的即时生效语义)。裸自动保存会把打到一半的 YAML 直接推给订阅方;草稿/发布两段式则改变用户心智并显著增加复杂度。
2. **版本粒度**:自动保存的防抖中间态会产生大量版本,全量保留会让历史列表全是噪音;手动快照则违背"自动"初衷。

## 决策

1. **编辑器**:CodeMirror 6 替换 Monaco,卸载 monaco 依赖;要求仅为高亮/折叠/缩进参考线/暗色跟随,不引入 LSP 级智能与 diff 视图(与轻量目标相悖)。
2. **校验门控自动保存**:编辑停止防抖约 1 秒,前端 YAML 解析通过才真正落库;不通过只本地标红。"落库即生效"语义不变——门控保证坏配置永远不落库,因此永远不可能流给订阅方。
3. **模板版本**:每次成功落库追加一个不可变版本(`template_versions`),每模板保留最近 20 个并裁剪,删除模板级联删除。
4. **回滚 = 新落库**:恢复旧版本 = 以其内容走校验门控通道再次落库,自身成为新版本;历史只追加,无破坏性操作。因此后端不需要专用 rollback 接口。

## 理由

- 门控自动保存是"免保存手感"与"不服务坏配置"的唯一交集:校验在落库前,生效语义不变。
- 版本粒度对齐落库事件而非时间或手动动作,语义最简单("每一个曾经生效过的配置")。
- 回滚复用现有 update 路径,行为天然满足"历史只追加";20 个裁剪上限压制防抖产生的中间版本噪音。
- CodeMirror 按需引入后页面 chunk 从 2304KB 降到 432KB(-81%)。

## 后果

- 显式保存按钮退出主通道(保留状态指示与手动等价物);非法内容切换模板仍弹确认(非法内容永不落库,切换即丢弃)。
- 预览历史版本时自动保存挂起,防止预览内容被防抖误落库;恢复必须显式确认。
- 存量模板不做版本回填:版本从下一次落库开始累积,当前内容始终为"生效中"。
- 前端新增 js-yaml(门控解析,~50KB),远小于卸载的 Monaco。
