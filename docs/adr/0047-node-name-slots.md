# 0047: 节点名称槽位模型(命名从节点注解翻转为用户资产)

- 状态: accepted
- 日期: 2026-08-10
- 关联: 设计文档 [design-node-name-slots](../design-node-name-slots.md); 触及 ADR 0012(名称标准化)的优先级语义、issue #51(刷新重算名称)、issue #83(收藏同表)、spec #84/#85(精选 alias)

## 背景

名称覆盖(`node_overrides.display_name`,以 `NodeKey = server:port[:SNI]` 为键)存在三个结构性缺陷:

1. **生效延迟**:改名只写库,覆盖层唯一生效点是机场刷新(`aggregator.go applyOverrides`),用户改名后往往要等数小时。
2. **静默孤儿化**:机场换 IP/端口即 node_key 变更,覆盖永远匹配不上,无任何提示。
3. **被标准化冲掉**:`StandardizeNodes` 无条件重算 DisplayName,`standardize_names` 开启时刷新即抹掉手动名(代码与 `aggregator.go:614` 注释不符)。

用户的核心工作流是:从机场挑出好节点 → 起统一的名字 → 订阅输出名字稳定 → 节点不行时把名字转给另一个节点。这是"名字是用户资产、节点是临时工"的心智,与"名字绑在 server:port 上"的现状模型根本相反。

## 决策

**翻转命名所有权:新建 `name_slots` 表,`(user_id, name)` 为主键,名字指向 node_key;双向唯一(一个节点在一个用户下只占一个槽位)。**

- 命名链(下发时实时求值):精选 alias > 槽位名 > 模板标准化 > 机场原名。精选 alias(spec #84)保留原位不废弃。
- 槽位在订阅生成时实时解析:改名/转移**下一次请求即生效**,不再依赖机场刷新。
- `StandardizeNodes` 跳过槽位节点(修复缺陷 3);"刷新名称"语义变为"重算未被接管节点的标准化名"。
- 转移是显式一等操作:占冲突返回 409 + 占用信息,前端确认后带 `force` 重试。**绝不自动改绑**;节点 stale 后槽位保留为空槽,走告警 + 界面亮灯,等用户指派。
- 存量 `node_overrides.display_name` 自动迁移为槽位;同名冲突 `updated_at` 新占旧让,旧行保留进"待处理冲突"人工兜底。`region`/`favorite` 不动。

配套(同一设计文档,决策记录于此):订阅节点监控(5 分钟 TCP 探活,3 败判宕/2 胜判恢复,飞书告警),监控集合在可用性/延迟过滤上**免疫**——宕机节点仍下发,用户可见"它还在,只是不可用";端点级开关的虚拟状态节点展示监控摘要。

## 后果

- 改名即时生效;同名撞车在模型层不可能(名字是主键)。
  ——**修订(issue #112/#113, 2026-08-14)**:槽位身份迁移为内部自增 ID 主键,
  (user_id, name) 唯一约束收窄为字面名(不含 {index})部分唯一索引。不变量改写为:
  **渲染结果不撞名;含 {index} 模板原文可重复**——同模板多槽位按 (前缀, 槽位名,
  槽位 ID) 排序从 01 自动编号(创建顺序),空槽不占号;不含 {index} 的字面名
  重名仍拒绝(409,文案提示加入 {index} 可自动编号)。双向唯一(一个节点一个槽)
  与转移 force 语义不变。
- 空槽成为一等状态:节点消失不再静默丢名,有告警有界面。
- 订阅生成路径每次请求需读槽位映射(带缓存失效);`/nodes` 管理视图与 `/sub` 共用同一生效名解析(WYSIWYG)。
- `PUT /nodes/override` 不再接受 `display_name`(400 拒收),命名只有槽位一个来源——消除"两套命名来源并存"的混乱。
- 监控与虚拟节点均默认关,存量实例零回归。
- 多租户语义继承 per-user 隔离;跨用户同 node_key 探测物理去重。
