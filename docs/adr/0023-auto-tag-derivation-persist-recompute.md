# ADR 0023: 自动标签 - 派生落库与重算时机

状态: accepted
日期: 2026-07-21

## 上下文

节点测试结果(解锁级别、出网质量、稳定性分、基准速率)散在 `node_health` 与 `exam_history` 两处,直接拿来做订阅筛选(见 [design-subscription-conditions](../design-subscription-conditions.md) 的 tag 维度)和表格列展示很笨重。需要一层**语义标签**(如 `nf-full`/`region:JP`/`stable-good`/`fast`)把原始指标归纳成可筛选、可展示的离散集合。

两个设计岔路:标签是**每次读时现算**还是**落库存储**?现算永不腐化但每次读都要聚合两张表;落库快但测试结果变了标签会滞后。

## 决策

### 1. 派生逻辑是纯函数

`nodetag.Derive(unlocks, report) []string`(`internal/nodetag/derive.go`)是无 IO 的纯函数:输入最新解锁判定 + 最近体检报告,输出去重、字典序排序的标签集合。无数据返回空切片而非报错。规则表(解锁 `(kind,level)->tag`、稳定性分档临界、fast 门槛)是包内常量,新增服务只加一行不改派生逻辑。

### 2. 落库存储,接受腐化

标签**落库**(节点 × 标签),不每次读时现算。明确接受"测试结果变了、标签暂时滞后"的腐化,以换取 `/nodes` 视图与订阅筛选的读性能。重算 = **全量替换该节点标签**(幂等)。

### 3. 重算时机(四个触发点)

- **批量解锁检测完成**后(按节点增量重算)。
- **每场深度体检完成**后(该节点,`onExamComplete` 收口三步之一)。
- **节点刷新上下线**时(清理死节点标签)。
- **夜间定时重算**(`retag_all` kind,兜底修正累积腐化,长在 [ADR 0019](0019-generic-async-jobs-runtime.md) 的 jobs 运行时上,可从游标续跑)。

## 后果

### 正面
- 订阅筛选与表格列直接读落库标签,不必每次聚合两张表。
- 派生纯函数易测(表驱动覆盖边界:分数临界/无数据/解析失败),规则表扩展成本低。
- 定时重算兜底,腐化不会无限累积。

### 负面
- 标签有滞后窗口:测试结果变化到下次重算之间,标签可能过时。这是"落库换读性能"的自觉代价。
- 派生规则表(标签词表)与 [design-subscription-conditions](../design-subscription-conditions.md) 的筛选维度、前端标签分组三处耦合,增删标签要同步。

### 被放弃的备选
- **每次读时现算**:永不腐化但每次 `/nodes`/订阅生成都要聚合两表,读放大,否决。
- **测试结果变化即时精确重算**:实现复杂(要追踪每个指标对哪些标签的影响),收益不抵成本;改为四个粗粒度触发点 + 夜间兜底。
