# ADR 0050: 名称槽位身份迁移与 {index} 模板重名放行

## 状态

accepted

## 日期

2026-08-17

## 上下文

ADR 0047 把槽位名定为主键,(user_id, name) 全局唯一。这带来两个互相关联的限制(issue #111 规格):

1. 含 {index} 的命名模板无法复用——模板原文被当字面值唯一化,而用户的心智是「模板 + {index} = 自动编号的一组名字」,最自然的命中路径(同一模板挂 N 个节点)在创建时就被 409 堵死;
2. 要放行重名,名字就不能再做主键,槽位需要不依赖名字的稳定身份。

## 决策

1. **槽位身份迁移为内部自增 ID 主键**(issue #112):name_slots 表经幂等表重建迁移(按 rowid 拷贝保创建顺序,created_at 无损);API 从按名寻址改为按 ID 寻址(PUT/DELETE `/api/slots/{id}`);行为对外零变化。
2. **(user_id, name) 唯一约束收窄为字面名部分唯一索引**(`WHERE name NOT LIKE '%{index}%'`):不含 {index} 的名字仍全局唯一(409),含 {index} 的模板原文可重复。
3. **不变量改写**(修订 ADR 0047「同名撞车在模型层不可能」):**渲染结果不撞名;含 {index} 模板原文可重复**。同模板多槽位按 (前缀, 槽位名, 槽位 ID) 排序从 01 自动编号(创建顺序,ID tiebreak 消除 map 迭代漂移),跨地区前缀各自成组,空槽不占号。双向唯一(一个节点一个槽)与转移 force 语义不变。
4. **WYSIWYG**:槽位列表的渲染预览与订阅输出共用同一编号求值路径(`computeSlotIndices`),列表展示真实分组序号而非恒 01。注意两处输入集不同:预览基于全量池,订阅下发基于过滤后候选集,槽位节点被过滤链剔除时两处序号可能漂移——同一求值函数、不同输入,属既有语义延续。
5. 409 文案给出可操作提示:字面名必须唯一,加入 {index} 可自动编号。

## 后果

- 同一命名模板可挂多个节点,自动编号(香港 01、香港 02),#111 的核心用户场景打通。
- 名字失去主键地位后,改名/重名放行不再触碰引用完整性;占用校验与摘下排除自身改按 ID。
- 「{index}」字面量判定存在于三处(store `SlotNameHasIndex`、DB 部分唯一索引 LIKE、server `slotIndexTmpl`),改占位符语法需三处同步——已知的轻量重复,接受。
- ADR 0047 原文不改(ADR 不可变),本 ADR 承载其不变量修订。

## 相关决策

- ADR 0047(名称槽位):本 ADR 修订其唯一性不变量,其余(双向唯一、空槽、转移 force、WYSIWYG 目标)全部延续。
