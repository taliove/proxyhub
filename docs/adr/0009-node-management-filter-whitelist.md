# ADR 0009: 节点管理——自建节点 CRUD + 机场节点屏蔽 + 关键词白名单

## 状态

已接受

## 上下文

"节点管理"的诉求横跨两类截然不同的节点,加上一个过滤能力缺口:

1. **自建节点**:store 层已有 Create/List/Delete(`self_hosted_nodes` 表),但无 API、无 UI,是埋了一半的功能;且缺 Update 和启停。
2. **机场节点**:聚合产出的快照,每轮刷新整体替换。手动删/停一个,下轮刷新就被冲回来——需要一个能跨刷新持久的机制。
3. **过滤方向**:系统设置只有关键词黑名单(排除),但用户的真实场景多是"只要香港/新加坡/美国/日本这几个地区",一个个拉黑不要的地区不如白名单只留想要的。地区自动识别只覆盖 7 个(HK/TW/JP/SG/US/KR),做"地区多选"会大量落到 Unknown,故白名单沿用关键词子串匹配而非地区枚举。

## 决策

三件事一并做:

- **自建节点四件套**:增 / 改 / 删 / 启停。store 补 `UpdateSelfHostedNode` 和 `SetSelfHostedNodeEnabled`,接上 API + 前端页(动态字段:按协议只显示相关字段)。
- **机场节点屏蔽**:新增持久的屏蔽名单(按 NodeKey `server:port` 精确匹配),节点页可屏蔽/取消屏蔽。命中的机场节点在订阅生成时剔除。语义是"屏蔽"而非"删除"——删除对刷新产物无意义。
- **关键词白名单**:系统设置新增一组关键词,与黑名单同套机制(子串、不区分大小写、订阅时生效、自建节点豁免),方向相反:非空时只保留命中的机场节点,为空则不启用。

**过滤顺序**(订阅生成时,承接 ADR 0005 的订阅时过滤层):

```
白名单(非空则只留命中) → 黑名单(剔除命中) → 机场屏蔽(剔除 NodeKey 命中) → 自建节点全程豁免
```

## 理由

- 粒度从粗到细:白名单粗筛地区,黑名单去假节点(如"香港·剩余流量"),屏蔽点杀个别坏节点。符合直觉。
- 白名单沿用关键词而非地区枚举:不受 7 个已知地区限制,想按地区/机场/任意关键词留都行,且复用既有 filter 代码。
- 机场屏蔽跨刷新持久,和关键词过滤同属订阅时过滤层(ADR 0005),不动聚合层——保持即时生效语义(ADR 0004/0005)。
- 自建节点是 FailBack 安全网(ADR 0001/0005),任何过滤都不动它。

## 后果

- 系统设置从"只有黑名单"变为"白名单 + 黑名单"两组关键词。
- 新增机场屏蔽名单的持久存储(settings 键或独立表)。
- 订阅时过滤链从"仅黑名单"扩展为三道,`keywordFilteredNodes` 演进为组合过滤;后台预览必须应用同一条链(所见即所得,ADR 0005)。
- 自建节点 `self_hosted_nodes` 表补齐 CRUD 全集。

- ADR 0005: 关键词过滤在订阅生成时生效(两阶段过滤)
