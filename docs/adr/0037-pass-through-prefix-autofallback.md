# ADR 0037: 直通前缀自动回退与 jsDelivr latest 解析

## 状态

accepted

## 上下文

ADR 0036 决策"不内置任何第三方镜像为默认"与"无静默回退",国内用户因此必须显式 `--download-base <镜像> --version <版本>` 才能完成安装。这是对的当时:没有签名信任锚,内置镜像与静默回退都不可接受。两个前提随后变化:

1. **签名信任锚已上线**(ADR 0036 同期实现):制品真实性由 minisign 验签保证,与传输通道无关——内置回退的完整性风险已消解,剩下的只有可用性(镜像 churn)与隐私(镜像运营方可见下载元数据)。
2. **国内用户的主流习惯是前缀直通站**(gh-proxy.com 形态:URL 前缀拼接即代理 GitHub),且明确要求"和国外一模一样的一条命令"——显式参数在这个习惯下是多余的摩擦。

实测(2026-07-31,本机):gh-proxy.com 前缀下入口脚本、制品、`.minisig` 均可达(200),latest 重定向不可靠(不重写到 tag URL);jsDelivr 数据 API(`data.jsdelivr.com/v1/packages/gh/<owner>/<repo>`)返回按新到旧排序的 tag 列表,可替代 latest 解析。

## 决策

1. **默认路径自动回退**:未显式给 `--download-base` 时,连通性自检 GitHub 失败 → 依次探测策展前缀列表(`PROXYHUB_GH_PREFIXES`,当前仅收实测可用的 gh-proxy.com),第一个可达的前缀接管下载基(拼官方基址),日志明示回退与"制品仍经验签保证"。全部不可达 → fail closed 并指引 `--download-base`。
2. **latest 解析双通道**:GitHub 重定向优先;不可达时回退 jsDelivr 数据 API(取首个稳定 semver)。仅自动回退路径享受该兜底;**显式镜像 + latest 维持 ADR 0036 的 fail closed**(显式 = 用户接管,契约不变;文档与既有测试不动)。
3. **显式参数优先于一切自动行为**:`--download-base` / `PROXYHUB_DOWNLOAD_BASE` 给出即跳过自动回退,按 ADR 0036 语义探测与使用。
4. **隐私告知**:回退流量经第三方前缀运营方(可见 IP 与下载行为),写入 DEPLOY.md 国内节;GitHub 永远第一选择,前缀只在 GitHub 不可达时启用。

本 ADR 取代 ADR 0036 决策 2 中"无静默回退"与"不内置镜像为默认"两条(其余决策不变)。回退非"静默":日志明示当前生效下载基。

## 理由

- 签名信任锚把"回退到第三方通道"从完整性问题降为可用性/隐私问题,而后两者可用"日志明示 + 文档告知 + 显式参数优先"约束住。
- 前缀直通站是国内用户既有习惯,自动回退让国内安装与国外入口同形:一条 `bash <(curl ...)`,交互式提示域名,其余全自动。
- 显式镜像维持旧契约,避免动摇已发布的文档与验收语义;自动路径的 jsDelivr latest 是纯粹增量。

## 后果

- 安装档案的 `DOWNLOAD_BASE` 可能记录前缀拼装的基址;update 沿用该基址,前缀失效时用户需显式 `--download-base` 覆盖(update 的自动回退留作后续)。
- 策展列表的维护是代码责任:前缀 churn 时更新 `PROXYHUB_GH_PREFIXES` 并发新版;列表失效的兜底文案(指引显式 `--download-base`)保证 fail closed。
- 隐私敏感的部署应显式 `--download-base`(自建反代)或走姿势 ①②(直通/自有代理),文档已写明。
