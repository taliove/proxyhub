# ADR 0020: 体检出网前置与全失败短路

状态: accepted
日期: 2026-07-21

## 上下文

[ADR 0017](0017-exam-orchestration-serial-stability-exclusive.md) 定下"各段串行、稳定性独占"的编排原则,当时只有三段(稳定性 -> 多地域 -> 解锁)。落地后两个问题暴露:

1. **出口信息埋在最后**:出口 IP/地区/DNS 是用户最想先看到的一眼画像,却排在解锁段之后,要等几十秒;而一个根本出不去的死节点,用户要等整场跑完才发现白等。
2. **死节点仍跑完全程**:若节点连出网都失败,后面的稳定性采样、多地域测速、解锁判定全是无意义的失败,既浪费墙钟又给出一份满是 error 的报告,甚至误落一条"高分"历史。

## 决策

### 1. 新增出网段并前置为第一段

体检从三段扩为四段,顺序固定为 **出网信息 -> 稳定性 -> 多地域测速 -> 解锁**:

- 出网段(`egress`)探测 IPv4/IPv6/DNS 三类小请求,用户开检 ~5s 内即见出口 IP/地区/DNS。
- 出网探测抽成 detection 包的模块化能力(`ProbeEgress`/`EgressProbe`),独立于体检编排,任何持节点会话的调用方都可复用(为单节点快测等场景铺路);体检出网段只是它的调用方之一。
- 出网段独占串行:跑完才进稳定性采样,不破坏 ADR 0017 的"稳定性独占"不变式。

ADR 0017 的串行与稳定性独占原则不变,本 ADR 只是把段序从三段调整为四段并把出网提到最前;0017 仍然有效,不被推翻。

### 2. 出网全失败短路

编排器在出网段结束后检查:IPv4/IPv6/DNS **三项皆失败(error)** = 节点根本出不去。此时:

- **短路后续段**:跳过稳定性/多地域/解锁,编排直接推 `error` 终态帧("出网全失败: 节点不可用")。
- **不落历史**:沿用取消/失败语义,短路的体检不写 `exam_history`(避免一条全 error 的坏历史)。

判定的边界钉死:**IPv6 不可达(`Available=false` 且 `Error=""`)是明确负判定,不算失败**——很多节点本就没有 IPv6,不能因此把整场判死。只有三项都带 error 才短路。此判定在后端(`egressAllFailed`,`internal/detection/exam.go`)与前端评分(`isEgressAllFailed`,`web/src/components/exam/score.ts`)各有一份,语义必须一致。

## 后果

### 正面
- 用户几秒内看到出口画像;死节点 fail-fast,不再空等整场。
- 坏节点不再污染历史与评分。
- 出网探测模块化后可被体检以外的场景复用,一处事实源。

### 负面
- 出网全失败的判定逻辑前后端各一份,新增/修改失败口径时两处必须同步(与 §7 回环断言"改一必查二"同类风险)。

### 被放弃的备选
- **出网段并行于稳定性以省时**:违反 ADR 0017 稳定性独占,否决。
- **短路仍落一条历史(标记不可用)**:与"成功完成才落盘"的既有语义冲突,且给历史时间线塞垃圾,否决。
