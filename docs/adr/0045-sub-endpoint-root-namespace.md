# ADR 0045: 订阅端点迁出 Site Path(根命名空间 /sub/ 双挂兼容)

## 状态

accepted

## 日期

2026-08-07

## 上下文

Site Path 是安装时生成的管理面隐藏路径:管理 UI、API 与订阅端点全部挂在 `/<site-path>/` 下,其余路径一律 404。设计意图是"不知道路径就连登录页都摸不到"。但订阅地址的构造把 Site Path 明文写进了每一条链接(`https://域名/<site-path>/sub/{path}?token=...`),而订阅链接的宿命就是扩散:进客户端配置、被转发分享、进各类日志。任何持链人都能拼出管理面入口,Site Path 这道防线对持链人完全失效(issue #74)。sitepath 保留字清单里早有 `sub`——订阅端点本就该在根命名空间,实现时没做到。

## 决策

1. **订阅端点迁到根命名空间 `/sub/{path}?token=...`**:sitePathMiddleware 在配置 Site Path 时精确放行 `/sub` 与 `/sub/*`,原样下放 mux(不剥前缀);管理面其余部分(SPA/API/登录/静态资源)继续只在 Site Path 下,边界不扩。
2. **双挂兼容,不设立退役时间表**(用户明确要求):旧形式 `/<site-path>/sub/...` 经既有剥前缀路径继续可用。历史已发出的链接不失效;双挂不削弱安全——两种形式都过同一 token 校验与 IP 过滤/限流链(它们在中间件链内侧,直通天然不受影响)。
3. **前端 URL 构造去掉 Site Path 前缀**:订阅管理列表、主页快捷端点、二维码内容统一为根命名空间形式。
4. **安装器 Caddy 站点块同步放行 `/sub/*`**:转发头替换语义与既有块一致;存量部署重跑安装器(幂等 regenerate)或手动补一段,文档(DEPLOY/SECURITY)写明迁移步骤。

## 后果

- 新复制的订阅链接不再制造 Site Path 泄露;已泄露的旧实例可通过既有 `proxyhubctl rotate-path` 轮换。
- 订阅端点的安全模型回归其本意:随机 path + token,公开可访问、不可枚举,不依赖路径隐藏。
- Site Path 的防护范围收窄为其该管的:管理面。SECURITY.md 早已声明它"不是密钥",本决策把实现与声明对齐。
- 运维注意:未同步 Caddy 配置的存量部署,新形式链接 404(旧形式照常),升级指引见 DEPLOY.md。

## 相关决策

- ADR 0035(Docker Caddy 安装模式)/ ADR 0039(站点块文件布局):站点块模板变更受其布局约束,两种形态共用同一生成函数。
- ADR 0033(拉取防护与全局 IP 拒止):根 /sub/ 直通不改变其防线位置与语义。
