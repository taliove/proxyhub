# ADR 0028: 订阅测试 — 内部链路验证与即时诊断不落库

## 状态
**已采纳** — 2026-07-22

## 背景

订阅地址(Endpoint)一直没有"测试"能力:用户把订阅发给终端后,无法在管理面回答两个基本问题——"这条链接现在能拉出东西吗"和"这份订阅现在的质量怎么样"。现有的「预览」只展示会下发的节点清单与原文,不做验证;「统计」只反映真实客户端的历史拉取。

需求讨论(grill 会话,2026-07-22)明确了三个设计分歧点,本 ADR 记录取舍。订阅测试的整体语义(三段式:拉取验证 → 池状态快照 → 可选现场实测)见 CONTEXT.md「订阅测试」。

## 决策

### 1. 拉取验证走内部生成链,不发真实 HTTP

验证逻辑直接复用订阅生成链(与预览同一条路:节点池 → 条件过滤 → 生成),检查产出内容的合法性(Clash YAML 可解析 / v2ray 行数正确)与节点数,**不向 `/sub/{path}` 发真实 HTTP 请求**。

理由:从服务器自己拉自己走 loopback,测到的只是生成链,测不到外网可达性(那取决于部署方式,管理面无能为力)——真实 HTTP 并没有比内部链路多验证任何有价值的东西,却会把测试拉取记进 `pull_logs`,污染拉取统计("老爸的手机半夜拉了 5 次"可能只是管理员自己点的测试)。统计的语义保持纯净:只反映真实客户端拉取。

被拒绝的替代方案:
- **真实 HTTP + 标记过滤**:连路由/鉴权一起验证更"真",但 loopback 下这些环节几乎不可能失败,却要为 pull_logs 加来源标记与统计视图过滤逻辑,复杂度换不到价值。
- **真实 HTTP 计入统计**:统计数字虚高,直接破坏统计的可信度。

### 2. 测试结果不落库,看完即走

订阅测试是即时诊断:每次触发现场算,展示完即弃,不写 `endpoint_test_runs` 之类的表。订阅列表若需展示"可用 x/y",直接从节点池状态实时计算(本来就是秒出的快照),不依赖历史测试记录。

理由:订阅地址的质量是节点池状态的**派生物**——池变了它就变,历史测试快照没有独立的行动价值(不像机场测试的历史趋势能反映机场本身的稳定性,那是告警与汰换决策的依据)。机场测试落库是因为列表要展示最近得分、异常面板依赖它;订阅测试没有这些消费方。

被拒绝的替代方案:
- **对称落库带历史**:多一张表 + 一套历史 UI,换来的趋势图是池状态的复读机。
- **只留最近一次(覆盖式)**:为"上次测试于…"这个时间戳引入持久化,不值。

### 3. 现场实测复用抽样检活核心,编排各自

可选的现场实测(对下发节点真实检活)与机场测试共享**无持久化的抽样检活核心**:地区分层抽样(优先区每层最多 5 个、其余每层最多 2 个)+ 检活 + 可用性写回,可一键升级全量。两种测试同一套交互,用户学一次就会。

实现方式:先做一次 prefactor,把机场测试 Orchestrator 中"抽样 + 检活 + 写回"抽成不依赖 run 持久化的独立核心,机场测试与订阅测试两处编排各自调用。**编排层不强行复用**——机场测试编排绑定 AirportID、8 处 run 持久化、评分含「拉取健康」维度(订阅测试无上游 URL,该维度无意义),整体复用会把两个不同的东西拧成一个。

### 4. 禁用态可测

订阅地址处于禁用状态时仍可在抽屉里触发测试——测的是"如果启用会下发什么",方便启用前验证。拉取验证走内部生成链(决策 1),天然不受 `/sub` 路由的启停拦截影响。

### 5. 现场实测的执行模型:裸 goroutine + 内存态 run

订阅测试的现场实测与机场测试同构:HTTP 层立即返回一个 run 句柄,后台 goroutine 执行,前端轮询进度。与机场测试的差异:run 状态**只存内存**(带过期清理),不写表——这是决策 2(不落库)的直接推论:重启即弃,用户重跑即可,对即时诊断定位无损失。

不进任务中心(jobs runtime):刷新、体检、机场测试(ADR 0027)是"长任务、要可见、要互斥",进任务中心合理;订阅测试是秒级到分钟级的即时诊断,轮询即可,为它在任务中心占一席反而稀释任务中心的定位。订阅实测因此有意与机场测试的执行模型不同构——它没有需要跨重启可见的任务语义。

## 后果

- 拉取统计语义不变,继续只反映真实客户端拉取;测试可以随便点,不留痕。
- 订阅测试无历史可查——如果未来出现"订阅质量趋势"的真实需求(如告警),需要回补持久化,届时推翻决策 2 的成本是一张新表 + 写入点,可控。
- 外网可达性仍无法从管理面验证;用户需理解"测试通过 ≠ 终端一定拉得到"(中间隔着部署网络)。
- 机场测试与订阅测试共享"验证 → 快照 → 实测"三段式语义;抽样检活核心经 prefactor 抽取后单一事实源,后续改抽样策略只需改一处;编排层(持久化、评分)则有意各写一份,未来任一侧演进不互相牵连。
- 现场实测的 run 状态在内存,服务重启后进行中的实测消失,前端轮询需容忍 run 不存在(提示重跑即可)。
