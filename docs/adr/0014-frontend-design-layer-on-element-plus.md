# ADR 0014: 前端留在 Element Plus 并自建设计层

## 状态
**已采纳** — 2026-07

## 背景

管理后台前端(`web/`)建立在 Element Plus 2.x 之上,当前观感与代码组织存在三个问题:

1. **默认主题模板感强**:沿用 EP 默认蓝(`#409eff`)与默认圆角/阴影,后台一看就是"Element Plus 模板",与想要的现代极简工具风(Linear/Vercel 式)差距明显。
2. **无令牌体系**:`styles/variables.css` 只有一层扁平变量,没有色彩刻度、间距刻度、语义分层;暗色主题靠逐变量硬改,新增主题维度成本高。
3. **样式失控**:全仓 116 处模板内联 `style`,页面级样式与组件样式混杂,无规范也无 lint 门禁,观感一致性靠运气。

需要决策的是:**底座怎么走**——继续在 Element Plus 上修补,还是换组件库,还是换整条技术路线。审美体系、页面模式、代码组织等具体规范本身不是本 ADR 的对象,落地细则见 [design-frontend.md](../design-frontend.md)。

## 备选方案与代价

### 方案 A:留 Element Plus + 自建设计层(采纳)

在 EP 之上建立自有令牌体系:原始刻度(tokens.css)→ 语义层(semantics.css,暗色只覆盖此层)→ EP 变量映射(ep-theme.css,全仓唯一书写 `--el-*` 的位置)。EP 的全部观感由 CSS 变量驱动,不改组件源码、不引入新依赖。

- **成本**:令牌体系与 ep-theme.css 的初始搭建(一次性);页面级样式整改(116 处内联清零,逐页进行)。
- **收益**:零迁移风险,全部页面与 EP 组件 API(表格、分页、抽屉、表单)原样可用;设计层的独立性使未来即使换组件库,刻度与语义层仍可复用。

### 方案 B:换组件库(Naive UI / Arco Design)

两者默认主题比 EP 更接近目标审美,主题机制也更现代。

- **成本**:全仓每个 view 的组件调用逐一改写;表格/分页/表单/抽屉的 API 与行为差异逐一回归;团队对 EP 的既有经验作废;Monaco 编辑器、vue-echarts 等周边集成需重新验证。这是一次全量重写,工作量以周计,且重写期间功能迭代冻结或双轨维护。
- **收益**:默认观感更接近目标,主题机制开箱即用。
- **判断**:收益是"少写一层主题映射",成本是"全量重写 + 回归风险"。方案 A 用一小层 ep-theme.css 即可获得同等观感控制力,收益/成本比明显更优。

### 方案 C:Tailwind CSS + 无头组件库(Headless UI / Radix Vue)

审美自由度最高,工具类样式与现代极简风天然契合。

- **成本**:同样要重写全部页面,且表格、分页、树、日期等复杂组件需自行在无头基座上拼装或引入第三方实现,工作量比方案 B 更大;utility-first 风格与现有代码习惯差异大;长期维护需要团队持续投入组件封装。
- **收益**:完全自主的视觉体系。
- **判断**:本项目是单人维护的本地工具后台,不是对外产品,没有"视觉完全自主"的需求强度;为此付出全量重写与自维护组件层的成本不成立。

## 决策

**留在 Element Plus,在其上自建设计层**(方案 A):

1. 组件库不变,不引入新框架、不换技术路线。
2. 设计层通过令牌三层架构实现,EP 变量映射收敛在单一文件(`ep-theme.css`),页面代码只允许消费语义令牌。
3. 品牌色由 EP 默认蓝替换为靛蓝系(`#4f46e5` 主色,9 级刻度),功能色与主色同明度饱和度体系。
4. 配套 lint 门禁(`vue/no-static-inline-styles`、`max-lines` 400)防止样式再次失控;存量问题按 Phase 0→3 分阶段整改(见 design-frontend.md),不做大爆炸重写。

## 后果

### 正面

- **零迁移风险**:所有页面、全部 EP 组件调用原样可用,改造可以逐页渐进进行,不阻塞功能迭代。
- **观感可控且可持续**:令牌三层使"调一个色值""改暗色表现""让 EP 换观感"各有唯一改动点;暗色主题成为一等公民而非补丁。
- **决策可逆**:原始刻度与语义层不绑定 EP,未来若确有换库需求,设计资产(色板、刻度、页面模式)仍然有效,沉没成本只有 ep-theme.css 一层。
- **门禁兜底**:lint 规则 + make lint-frontend 使规范不依赖自觉,116 处内联样式这类问题不会再生。

### 负面

- **EP 观感改造的边界**:EP 未暴露 CSS 变量的细节(个别组件内部间距、动效)仍需类选择器微调,这些补丁集中在 ep-theme.css,属已知且被收敛的成本。
- **双体系心智**:开发者需要理解"语义令牌"与"EP 变量"的关系,新手上手有一道文档门槛——由 design-frontend.md 承担。
- **方案 B/C 的原生优势被放弃**:换库路线的"默认即美"没有了,目标观感要靠自建设计层达成并持续维护。

### 否决项记录

- **Naive UI / Arco Design**(方案 B):全量重写成本与"少写一层主题映射"的收益不成比例,否决。
- **Tailwind + 无头组件库**(方案 C):重写 + 自维护组件层的成本超出本项目的视觉自主需求强度,否决。
