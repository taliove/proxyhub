# ADR 0022: 体检总分 - 四项加权与渐进/归一双模式

状态: accepted
日期: 2026-07-21

## 上下文

四段体检各自出一堆指标(稳定性分、各区速率、解锁级别、出网质量),用户需要一个**一眼可比**的总分。设计总分要回答三个问题:

1. **怎么加权**:四段贡献不等,稳定性最重要,出网质量是减分项。
2. **进行中怎么显示**:体检 ~80s 逐段到达,若一开始就按"已到达段归一化"算分,出网段一到就显示满分,严重误导("刚开测就 100 分")。
3. **缺段/失败怎么处理**:某段跑不出(缺数据)、或出网根本失败,总分该如何取值才不骗人。

## 决策

总分是从 `ExamReport` 派生的**纯函数**(`calculateExamScore`,`web/src/components/exam/score.ts`),不落存储,报告卡/分享卡/历史卡共用。

### 1. 四项加权(权重和 = 100%)

- **稳定性 40%**:直接用稳定性段的 0..100 分。
- **速度 25%**:基准行(Cloudflare 就近 POP)下行对数映射锚点(≥100M→100 / 50M→85 / 25M→70 / 10M→50 / 5M→30 / 1M→10,锚点间线性插值),上行 ±5 微调。
- **解锁 20%**:6 目标 `full=1 / originals_only=0.5 / 其他=0` 取均值 ×100。
- **出网质量 15%**:100 起扣(DNS 泄露 −30、机房 IP −15、无 IPv6 −10,保底 0)。

档位:90+ 极好 / 75+ 良好 / 60+ 一般 / 40+ 较差 / <40 很差。

### 2. 渐进 / 归一双模式

同一份加权公式,靠一个 `mode` 参数切两种缺段处理:

- **`progressive`(进行中)**:未到达段计 **0 分**,不归一化。总分从低往高爬——出网段先到只贡献满分 15,四段全到才可能满分。避免"开测即高分"的误导。
- **`normalized`(完成态/历史/分享)**:缺段按有数据项**归一化权重**(权重和放大回 100%)。已定型的报告即便缺某段,也应就已有维度给出公允的满量程分。

两模式在四段全有数据时**完全等价**(归一化因子为 1)。任一模式下有段缺失都标 `partial=true`,UI 显示"部分数据"。

### 3. 可信度:出网是分数的地基

- **出网全失败**(三项皆 error,判定同 [ADR 0020](0020-exam-egress-first-and-shortcircuit.md)):总分强制 **0** 且标 `unreliable`(与 mode 无关)。
- **缺出网段**:同样标 `unreliable`——没有出口画像的分数不可信。

进行中不显示具体高分数占位(显示"—"/"评估中"),避免误导。

## 后果

### 正面
- 一个 0..100 总分 + 五档,跨节点/跨次可比;进行中分数单调爬升,符合直觉。
- 完成态对缺段公允(归一化),进行中对缺段诚实(计 0),两种诉求靠一个参数统一,不写两份公式。
- 出网作为可信度地基,杜绝"出不去却高分"的假象。

### 负面
- 权重与锚点是经验值(40/25/20/15、速度锚点表),调整需重新校准跨次可比性。
- 渐进/归一的等价性依赖"四段全到归一化因子=1"这一不变式,新增段或改权重时必须保持。

### 被放弃的备选
- **只按已到达段归一化(单模式)**:进行中"开测即满分"误导,否决;拆出 progressive 模式。
- **总分落库**:指标口径会演进,落库即固化旧口径;改为纯函数从报告实时派生,历史报告用新公式重算。
