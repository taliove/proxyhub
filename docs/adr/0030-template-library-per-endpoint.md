# ADR 0030: 配置模板升级为用户级模板库,订阅地址可按需选定

## 状态

已接受

## 上下文

ADR 0006 决策"单一全局模板"的前提是:用户开多个订阅地址的动机是"给不同设备分发",不是"给不同设备用不同规则"。多用户架构(ADR 系列多租户工作)与真实分发场景推翻了这个前提:用户把不同订阅地址分发给不同的人(朋友 A/B),不仅想控制"下发哪些节点"(已由订阅地址 conditions 解决),还想控制"下发的配置骨架长什么样"——给老手完整分流规则与地区分组,给小白一个只有"自动选择"的精简骨架。

ADR 0006 已为此预留扩展口("可加一个可选的 template_id 字段")。本决策落地该扩展,但形态不是每订阅地址一份内联模板,而是**模板库 + 订阅地址挑选**:模板是用户级命名资源,可在多个订阅地址间复用。

## 决策

1. **模板库**:`template` 表从"每用户单行(name='clash')"升级为"每用户多套命名模板",加 `is_default` 标记与 `UNIQUE(user_id, name)`;现有用户模板迁移为库成员并标默认。库归用户所有,随用户空间隔离。创建受 `max_templates` 配额约束(默认 10,超管可调)。
2. **订阅地址引用**:`endpoints.template_name`(空串 = 跟随默认)。创建/编辑订阅地址时可从库中挑选。
3. **四级回退链**:渲染 Clash 订阅时按 订阅地址选定 ?? 用户默认模板 ?? 超管全局默认(`system_settings.clash_template`)?? 内嵌默认 解析,每级 miss/空继续下落,永不因模板缺失报错。
4. **软引用**:删除一套被引用的模板允许,引用它的订阅地址自动回退(按名查找 miss 即下落,不做级联数据改写);删除接口返回引用数供前端提示。绑定不存在的模板在写入侧 fail-fast(400)。

## 理由

- **库 + 挑选**优于内联定制:同一套骨架("小白版")可绑给多个订阅地址;改库成员即对所有绑定方生效,与 ADR 0006"改一次处处生效"的维护性论证一致。
- **软引用 + 回退**优于硬引用禁止删除:回退链本来就是系统的核心语义(租户级设置同款),"模板没了下落一级"与"没挑模板"行为一致;分发出去了的订阅地址不会因删模板而渲染失败。
- **每级下落不报错**:订阅地址是公开端点,渲染必须永远有产出(链底是内嵌默认,永不失败)。

## 后果

- ADR 0006 的"单一全局模板"语义收缩为链底两级(超管全局默认 + 内嵌默认),其"订阅地址共享"前提被本决策取代;0006 追加演进说明并链接本 ADR。
- 迁移守卫按"template 表是否已有 is_default 列"判定并包裹在单事务内——早期实现按中间表 `template_library` 是否存在判定,重命名后每次重启重建、自定义默认被重置(回归测试 `TestTemplateLibraryMigrationPreservesDefault` 锁定)。
- 旧"用户模板"读写助手(`GetClashTemplateForUser` 等)改为库实现,外部语义不变。
- V2Ray 格式仍不走模板(同 ADR 0006)。
- 渲染入口从 `renderSubscription` 扩为 `renderSubscriptionForEndpoint`(需 endpoint 上下文)。
