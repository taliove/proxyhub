# ADR 0007: 占位符语法使用 Mustache 风格 `{{nodes}}`

## 状态

已接受

## 上下文

配置模板(ADR 0006)里,策略组的 `proxies` 数组需要引用"当前所有节点"。但节点池每次聚合都在变(机场节点名、可用性都是动态的),模板不能硬编码节点名——参考的专业机场配置在 42 个策略组里各硬编码了 337 个节点名,完全无法维护。

需要一种占位符机制,让模板作者"引用节点集合"而非具体节点。

## 决策

采用 Mustache 风格的 `{{nodes}}` 占位符,作为 `proxy-groups` 中某个组 `proxies` 数组里的一个**数组元素**。渲染时:

1. 顶层 `proxies` 字段由聚合系统动态生成(每个节点的完整代理配置)
2. 遍历所有 proxy-group,把值为 `{{nodes}}` 的数组元素替换为全部节点名
3. 其余字段(hosts/dns/rules)原样保留

节点名先去重(Clash 要求唯一),组里展开的名称与 `proxies` 字段里的名称严格一致。同一组内重复的占位符只展开第一次。

MVP 仅支持 `{{nodes}}` 一种占位符。

## 理由

- Mustache 风格开发者普遍熟悉,可读性强,与 YAML 的引号语法('{{nodes}}')不冲突
- 作为数组元素(而非整行文本替换)让渲染基于 YAML 结构而非字符串,能正确保留 DIRECT/REJECT 和对其他组的引用
- 默认模板用一次性脚本从参考配置转换而来:把每个组里的裸节点名折叠成单个 `{{nodes}}`,保留组引用与内置策略

## 后果

- 模板作者只需在"根选择组"写一次 `{{nodes}}`,其余应用组引用该组名即可复用节点选择
- 渲染走 YAML 解析(`yaml.Unmarshal` → 改 map → `yaml.Marshal`),而非文本替换——健壮但对超大模板(默认约 15k 行 rules)有约 30ms 开销,可接受
- 未来若需按地区/可用性筛选,可扩展 `{{nodes_region_香港}}` 等,不破坏现有 `{{nodes}}`
