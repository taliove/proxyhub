# ADR 0024: 机场测试 — 诊断只读 + 抽样检活写回 + 综合评分

## 状态
**已采纳** — 2026-07-21

## 背景

多机场接入后,管理员无法回答两个日常问题:

1. **这个机场现在健康吗?** 机场订阅挂掉(URL 失效/被墙/格式变更)只能等全局刷新后从节点消失间接发现,定位靠手动 curl。
2. **哪个机场值得留?** 健康检查结果全池混合,没有按机场维度的质量视图,续费/退订决策凭感觉。

由此引入「机场测试」(术语见 CONTEXT.md):对单个机场手动触发的整体评价。设计时有三个真实 trade-off 需要记录。

## 决策

### 1. 语义拆分:拉取诊断只读,抽样检活写回

机场测试流水线 = 拉取诊断 → 分层抽样检活 → 综合评分。两个阶段的写回语义不同:

- **拉取诊断只读**:对机场订阅 URL 拉取并解析,报告 HTTP 状态/耗时/节点数/协议分布/解析失败行数,**不触碰节点池**。出问题的机场可以反复测试而不影响在线状态。
- **抽样检活写回**:对样本节点跑既有两阶段健康检查,结果经 `UpdateNodeTestResult` 写回节点可用状态/延迟——与全局健康检查**同函数同语义**。

为什么检活要写回(而不是"测试就该无副作用"):检活结果是真实的新鲜信号,藏着不用反而让节点池落后于事实;且抽样只覆盖部分节点,写回是逐节点的,不会波及未测节点。复用同一写回路径保证测试口径与日常检活一致,横向对比才有意义。

### 2. 分层抽样而非全量

机场节点数可达几十上百,全量两阶段检活要几分钟,交互上等不起。抽样规则:

- 按 `nodes.region` 分层;**优先区 HK/SG/US 每层最多 5 个,其余地区每层最多 2 个**,无地区信息归入 UNKNOWN 层按其他区配额
- **层内随机**选取(`rand.Shuffle`)
- 报告内可「跑全量」升级(`{"full": true}`),覆盖该机场全部节点

优先区配额反映维护者的实际使用分布(港台新美是主力落地)。层内随机保证无偏——多次测试的分数波动反映真实质量波动;「可用优先」抽样会系统性高估分数、掩盖节点池坏死程度,「固定顺序」抽样可能恰好踩中同机房线路,均被拒绝。

### 3. 综合评分权重

0-100 综合分,四维度加权:

| 维度 | 权重 | 说明 |
|---|---|---|
| 可用率 | 50% | 样本中可用节点比例,质量的第一信号 |
| 延迟 | 30% | mean 15% + p95 15%,线性映射(≤100ms 满分,≥1000ms 零分) |
| 拉取健康 | 10% | HTTP 2xx 且解析成功率 |
| 地区覆盖 | 10% | 命中地区数,优先区各 2 分、其他区各 1 分,上限 10 |

可用率占半:机场测试的首要问题是"还能不能用",延迟与覆盖是第二阶调优信号。权重是判断而非测量,后续可按使用反馈调整——维度明细随 run 落表,重定权重时可离线重算对比。

### 4. 结果落表,列表可见

每轮测试落 `airport_test_runs`(抽样参数、是否全量、状态、综合分、维度明细 JSON),保留 90 天(挂入既有 maintenance 清理 job,与 audit_logs/pull_logs 同风格)。机场列表 API 用 LEFT JOIN + 子查询一次带出每机场最近一轮得分(避免 N+1),列表"最近测试"列支撑横向对比与历史趋势。

## 被拒绝的替代方案

- **单机场聚合写回(测试含 pool merge)**:测试语义变成"如果现在刷新会怎样",机场订阅故障会把该机场节点整批标 stale,测试不再安全;全局刷新已覆盖该需求。
- **完全只读沙盒**:检活结果不落任何状态。最安全但浪费真实信号,且与全局检活口径分裂。
- **可用优先抽样**:分数系统性偏高,掩盖节点池坏死。
- **固定顺序抽样**:可复现但样本可能踩中同机房同线路,评估失真。
- **自动触发(定时/刷新后联动)**:本次仅手动触发,控制后台负载;列为演进项。
- **subscription-userinfo 流量/到期探测**:评估后未采纳(机场支持度不一,价值/成本比低)。

## 后果

- 「测试会改节点状态」需要用户心智:对话框与文档中检活阶段明示"结果写回节点池"。
- 抽样评分是估计值:小机场(节点 < 配额)等于全量;大机场分数带采样噪声,趋势比单轮绝对值更可靠。
- 新增表 `airport_test_runs` 与 3 个 API(`POST /api/airports/{id}/test`、`GET .../runs/{runId}`、`GET .../runs`),均走 requireAuth。
