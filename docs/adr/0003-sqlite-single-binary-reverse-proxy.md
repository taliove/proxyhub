# ADR 0003: SQLite 单文件存储 + 单二进制部署 + 反向代理 TLS

## 状态

已接受

## 上下文

系统需要持久化：订阅地址配置（随机 Path/Token/别名）、拉取统计（IP × 次数 × 地理位置）、IP2Ban 封禁记录、节点健康历史。

用户明确要求：
- 部署方式必须极简：下载二进制，放到目录里直接启动
- 数据存储必须简单，不引入复杂组件
- 服务通过 HTTPS 访问

## 决策

1. **存储：SQLite 单文件**，使用纯 Go 驱动（`modernc.org/sqlite`，无 CGO），数据库文件放在程序工作目录下
2. **部署：单二进制**，交叉编译为 Linux amd64，无外部运行时依赖
3. **TLS：由反向代理（Caddy/Nginx）终结 HTTPS**，程序只监听本地 HTTP 端口

## 备选方案

- **JSON 文件存储**：直观可手改，但统计聚合查询（按 IP/地址/时间分组）需要自己实现，数据量增长后性能差，且并发写需要自己处理锁
- **嵌入式 KV（bbolt）**：单文件、纯 Go，但无 SQL 查询能力，统计分析场景写起来繁琐
- **程序内置 TLS（autocert）**：少装一个组件，但把证书管理耦合进程序；腾讯云环境下用户更习惯用反代 + 已有证书

## 理由

- SQLite 满足"单文件、零运维"的要求，同时保留 SQL 聚合查询能力，正好覆盖统计需求
- 纯 Go 驱动保证交叉编译出的仍是静态单二进制，不破坏部署极简性
- 备份 = 拷贝一个文件
- TLS 交给反代，程序逻辑更简单，证书轮换与程序发布解耦

## 后果

### 正面
- 部署流程：`scp` 二进制 + 一个 config.yaml → 启动，完成
- 数据迁移/备份极其简单

### 负面
- 纯 Go SQLite 驱动性能低于 CGO 版本（本系统规模下完全无感）
- 需要用户自行配置一次反向代理（提供文档模板）

### 中性
- 单写者模型：SQLite 并发写有限，但本系统写入频率极低（15 分钟一轮检查 + 偶发拉取），无压力
