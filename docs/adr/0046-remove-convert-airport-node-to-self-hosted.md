# 0046: 撤销机场节点转自建能力

- 状态: accepted
- 日期: 2026-08-08
- 关联: issue #89; 撤销 issue #56/#81(spec #70 相关票据)引入的 `POST /api/self-nodes/from-pool`; 触及 ADR 0001 的自建节点去重豁免语义

## 背景

#56/#81 提供了一键把池内机场节点转为自建节点的能力(服务端映射连接参数落 `self_hosted_nodes`)。测试线验收暴露结构性冲突:转换后同一物理节点以两个身份共存于下发池——机场订阅原节点 + 自建副本,NodeKey 完全相同。下发链去重(`deduplicateNodes`)对自建节点豁免("避免与机场节点 NodeKey 碰撞时被并掉",ADR 0001 时代假设碰撞仅偶发),于是同一节点重复下发:精选按 NodeKey 白名单匹配两份都命中(精选 2 个拉到 3 个),全量订阅同样重复。

## 决策

**撤销机场节点转自建能力**:删除 `POST /api/self-nodes/from-pool` 路由、handler 与池节点到自建草稿的映射。自建节点只来源于「添加自建节点」——手动录入真正自己搭建的服务。

理由(用户决策):机场订阅节点转自建没有意义;自建就是真正自己去搭建的服务。转换造出的"自建"节点仍依赖机场侧的存活与参数漂移,不具备自建的独立性,反而引入双身份重复。

## 后果

- 任何节点在订阅下发中只出现一份(恢复正常路径;手工录入与机场节点同 server/port 的自建节点属用户显式行为,维持既有"两份都留"的豁免语义,不改 `deduplicateNodes`)。
- 前端本无能见入口(API-only 能力),无 UI 改动。
- 已存在的转换产物(既有自建节点行)不做数据迁移,用户可在节点管理手动删除。
- 精选(issue #79/#85)的 NodeKey 白名单语义不变。
