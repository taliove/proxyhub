# 前端设计规范 - 设计

## 概述

本文档是 ProxyHub 管理后台前端(`web/`)的设计规范,回答一个问题:**新页面该怎么写**。

现状问题:界面沿用 Element Plus 默认主题(#409eff 默认蓝),模板感强;样式分散在各 view 的内联 `style` 属性与零散 class 中(全仓 116 处内联样式);`styles/variables.css` 只有一层扁平变量,无色彩刻度、无间距刻度、无语义分层,暗色主题只能逐变量硬改;页面代码为平铺单文件,最大的 view 已超过 900 行。

规范内容:令牌三层架构、靛蓝色彩系统、列表页/详情页两种标准页面模式、页面目录制代码组织、lint 门禁规则。底座选型(留在 Element Plus 并自建设计层)的决策过程与否决项见 [ADR 0014](./adr/0014-frontend-design-layer-on-element-plus.md),本文只引用结论,不重复论证。

## 底座

组件库继续使用 **Element Plus**,不引入新框架、不换组件库。设计层通过 CSS 自定义属性覆盖实现:Element Plus 的全部观感由 `--el-*` 变量驱动,我们在其上建立自有令牌体系并做唯一映射(见"令牌三层架构")。审美、布局、代码组织层面的规则由本规范定义,不依赖组件库默认行为。

## 审美方向:现代极简工具风

对标 Linear / Vercel 类开发者工具后台,落到具体规则是五条:

1. **灰阶为主,用色克制**。界面 90% 由中性灰阶构成;品牌靛蓝只出现在主行动按钮、激活态、链接、焦点环;功能色只表达状态语义,不做装饰。
2. **轻阴影,靠描边分层**。卡片与浮层以 1px 描边区分层级,阴影只在悬浮/浮层场景出现,且透明度低、扩散小。
3. **高密度**。面向管理员的工具界面优先信息密度:表格行高紧凑、控件默认 `small` 尺寸、间距取自 4px 基网刻度,不允许自由发挥。
4. **暗色一等公民**。暗色不是反色滤镜,表面色、文本色、描边、阴影均有独立暗色取值;暗色只覆盖语义层(见令牌三层架构)。
5. **无多余装饰**。不用渐变、不用大圆角、不用彩色背景块堆砌;视觉层级靠字重、字号、灰阶深浅表达。

## 令牌三层架构

令牌按职责分三层文件,位于 `web/src/styles/`:

```
tokens.css      原始刻度(主题无关的"尺")
semantics.css   语义令牌("这个词是什么意思")
ep-theme.css    Element Plus 映射("EP 怎么穿这套衣服")
```

### 第一层:tokens.css — 原始刻度

只放不带语义的原始刻度:全部色板(indigo-50..900、gray-50..900、功能色基色)、间距刻度、字号刻度、圆角刻度、阴影刻度、z-index 刻度。**亮暗主题取值不同的一律不放这一层。**

具体刻度值:

**间距(4px 基网,space-1..8)**:

| 令牌 | 值 | 典型用途 |
|---|---|---|
| space-1 | 4px | 图标与文字间距 |
| space-2 | 8px | 控件间距、紧凑内边距 |
| space-3 | 12px | 表单项间距 |
| space-4 | 16px | 卡片内边距、区块间距 |
| space-5 | 24px | 区块间距 |
| space-6 | 32px | 页面区块间距 |
| space-7 | 48px | 大区块分隔 |
| space-8 | 64px | 页面级留白 |

**字号**:text-xs 12px / text-sm 13px / text-base 14px(正文基准)/ text-md 16px / text-lg 18px / text-xl 20px / text-2xl 24px。表格内次要信息用 text-sm。

**圆角**:radius-sm 4px(控件)/ radius 6px(默认)/ radius-lg 8px(卡片)/ radius-xl 12px(抽屉、浮层)/ radius-full 999px(标签、胶囊)。卡片(`el-card`)统一用 radius-lg,不用 radius。

**阴影**(亮主题基准):shadow-sm `0 1px 2px rgba(15,23,42,0.05)` / shadow `0 2px 8px rgba(15,23,42,0.08)` / shadow-lg `0 8px 24px rgba(15,23,42,0.12)`。暗色阴影在 semantics 层覆盖同名令牌:`rgba(0,0,0,0.3 / 0.4 / 0.5)` 递进(暗底上蓝灰阴影不可见,必须用纯黑)。

**z-index**:z-sticky 100(表头吸附)/ z-fixed 500(侧栏、顶栏)/ z-dropdown 1000(下拉)/ z-overlay 2000(遮罩)/ z-drawer 2010(抽屉)/ z-dialog 2020(对话框)/ z-message 3000(全局消息)/ z-tooltip 4000。页面代码不允许出现刻度外的 z-index 字面量。

### 第二层:semantics.css — 语义令牌

把原始刻度赋给语义名:`--ph-color-primary`、`--ph-bg-page`、`--ph-bg-surface`、`--ph-text-primary`、`--ph-border`、`--ph-radius`、`--ph-shadow` 等(沿用现有 `--ph-` 前缀)。**暗色主题(`html.dark`)只覆盖这一层**——页面与组件只消费语义令牌,暗色切换不需要动任何页面代码。现有 `dark.css` 的覆盖方式正是这一层的雏形,Phase 1 将其归位进 semantics.css。

### 第三层:ep-theme.css — Element Plus 映射

全仓**唯一**允许书写 `--el-*` 变量的文件。把语义令牌映射到 EP 变量(`--el-color-primary`、`--el-bg-color`、`--el-text-color-primary`、`--el-border-radius-base` 等),EP 组件因此自动穿上设计层。EP 未暴露变量的细节样式(如表格行高)也只在 ep-theme.css 内以 EP 类选择器微调,不散落到页面。

**例外:EP 变量必须有暗色块。**"暗色只覆盖 semantics 层"对 EP 变量不成立——element-plus 的 `dark/css-vars.css` 用 `html.dark` 选择器写字面量,特异性高于 `:root`,与加载顺序无关。因此 ep-theme.css 必须在 `html.dark` 块中重复声明全部映射(引用 semantics 变量,不写新字面量),否则暗色下 EP 变量回落到 EP 默认暗色。亮主题的 light-N 混白/dark-2 混黑 20%;暗主题按 EP 暗色惯例反转(light-N 混黑、dark-2 混白 20%)。

### 修改纪律

| 要做什么 | 改哪层 |
|---|---|
| 调一个具体颜色/间距/圆角的值 | tokens.css |
| 让暗色下某处观感不同 | semantics.css 的 `html.dark` 块 |
| 让 EP 某组件换观感 | ep-theme.css |
| 写页面/组件样式 | 只消费 semantics.css 的语义令牌,**禁止**直接引用原始刻度,禁止写 `--el-*`,禁止内联 style |

## 页面模式

后台页面只有两种标准模式:**列表页**与**详情**。新页面先归入其一,套对应骨架。

### 列表页标准骨架

```
┌─────────────────────────────────────────────────────┐
│ 页面标题                          [全局操作 ▼]       │
├─────────────────────────────────────────────────────┤
│ 筛选区:控件 change 即生效;超过 4 项收进"更多筛选"   │
├─────────────────────────────────────────────────────┤
│ 批量栏(仅当选中数 > 0 时出现):已选 N 项 + 批量操作  │
├─────────────────────────────────────────────────────┤
│ 表格区                                               │
├─────────────────────────────────────────────────────┤
│ 分页区                                               │
└─────────────────────────────────────────────────────┘
```

规则:

1. **筛选区收敛**。筛选控件 `change` 即触发查询,不设"查询"按钮;超过 4 个筛选条件时,第 5 个起收进"更多筛选"折叠区。文本搜索用 `clearable` + 回车/清空触发,不做防抖以外的延迟。
2. **批量栏上下文化**。未选中任何行时批量栏不渲染;选中后才出现,显示"已选 N 项"与针对选中集的操作。批量栏不承载与选中集无关的常驻操作。
3. **全局操作收右上角下拉**。与选中集无关的页面级操作(导入、清理、批量检测等)统一收进标题行右侧的下拉菜单,不在页面上平铺按钮墙。当前 Nodes 页批量栏里混排的检测/清理/按机场屏蔽等按钮,Phase 2 整改时按此规则归位。
4. **危险色纪律**。`danger` 只给不可逆操作(删除、清理、屏蔽);可逆操作(取消屏蔽、停用)用默认或 warning。同一视觉区域内 danger 按钮不超过一个主显,其余收进下拉。
5. **表格行内操作**不超过 3 个,超出收进行内下拉;行点击/"查看"一律打开详情抽屉。

### 详情模式

1. **右侧抽屉是唯一详情容器**。任何"查看某条记录详情"的需求都用 `el-drawer` 右侧滑出,宽度两档:480px(纯字段展示)/ 640px(含子表或富内容)。禁止新开路由页做详情,禁止用 dialog 堆详情。
2. **expand 展开行禁用**。表格 `type="expand"` 展开行一律不再使用。唯一豁免是真主从结构(一行自带一份独立子表,如节点及其解锁检测结果清单)——豁免需逐案评审,且主从内容同样优先放抽屉。Nodes 页现有 expand 行在 Phase 2 按此规则改造。
3. **dialog 与 drawer 语义分离**。`el-dialog` = 操作(表单提交类:新建、编辑、确认);`el-drawer` = 查看(详情展示)。不允许用 dialog 展示详情,也不允许在抽屉里嵌大表单;抽屉内只允许轻量行内操作。

## 代码组织

### 页面目录制

view 从平铺单文件改为目录制:

```
views/<page>/
  index.vue          装配层:布局 + 组合子组件/ composable,不含业务逻辑,<150 行
  components/        页面私有组件(只被本页使用)
  composables/       页面私有逻辑(数据获取、筛选状态、批量操作)
```

### 拆分纪律

1. **view 超过 400 行必拆**。当前最大的 Nodes.vue 已超 900 行,是 Phase 2 首个整改对象。
2. **拆分优先级:先 composable 后组件**。优先把数据获取、状态机、批量操作抽成 composable;只有模板块确实独立复用或过长时才抽组件。避免为拆而拆出一堆一次性组件。
3. **私有组件不进全局目录**。只服务单页的组件留在该页 `components/` 下;`src/components/` 只放跨页复用的通用组件,且进入前需确认至少两个页面使用。
4. index.vue 作为装配层,超 150 行说明拆分不彻底。

## 门禁规则

规范靠工具执行,不靠自觉:

1. **ESLint + Prettier** 落地 `web/`,作为前端代码风格唯一事实源。
2. 关键规则:
   - `vue/no-static-inline-styles` — 禁止静态内联 `style`,既有 116 处清零是 Phase 2 各页验收的一部分;动态绑定 `:style` 不在禁列,但应优先用 class。
   - `max-lines`(400 行)— 与"view 超 400 行必拆"对齐。
   - 阶段内以 **warn** 起步,不阻塞既有代码合入。
3. **入口**:`make lint-frontend` 为唯一 lint 入口(对齐 CLAUDE.md §5 的 make 入口基本法),并入 `make check` 聚合。
4. **warn → error 收网条件**:Phase 2 全部页面整改完成、存量告警清零后,上述两条规则升为 error(Phase 3),此后新增违规直接阻塞 `make check`。

## 落地阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| Phase 0 | 本文档 + ADR 0014 | 评审通过 |
| Phase 1 | 基建:tokens/semantics/ep-theme 三层落地、暗色归位、ESLint+Prettier+make lint-frontend 接入 | 全站观感切换为靛蓝体系,暗色正常 |
| Phase 2 | 逐页整改,Nodes 先行(代码最重、模式最全),按列表页/详情模式套骨架,清零内联 style | 每页:内联 style 为 0、view ≤400 行、过 lint warn |
| Phase 3 | 收网:lint 规则 warn 升 error | `make check` 对新增违规硬阻塞 |

各阶段对应 ticket 见 `.scratch/frontend-design-system/issues/`(过程稿,落地后随 .scratch 消亡;持久知识以本文档与 ADR 0014 为准)。

- 流量分发页的领域设计(字段、流程)见 [design-distribution-frontend.md](./design-distribution-frontend.md),本规范只约束其观感与代码组织,Phase 2 整改时不改其领域行为。
- 术语(机场/节点/订阅地址/屏蔽等)以 [CONTEXT.md](../CONTEXT.md) 为准,界面文案不得另造词。
