# 本机实测(浏览器端测速)- 设计

## 定位

回答"我此刻这条链路真实体验如何"(验收),与体检/快速测速(ProxyHub 主机经节点的筛选性测量)互补。术语与边界见 [CONTEXT.md](../CONTEXT.md)「本机实测」;本文记实现口径,随代码演进。

## 架构

纯浏览器 JS 对 ProxyHub 服务端自建端点测速,测量 = 浏览器 → ProxyHub 主机链路,上限 = min(服务端带宽, 客户端带宽)。ProxyHub 不感知、不控制客户端(TAG 等)的节点选择:浏览器走什么链路就测什么链路,测前由用户从节点池下拉手动标注本次链路对应节点(或"直连")落库。

- 端点挂管理面 `/api/speedtest/*` 且过 requireAuth(下行发流是带宽放大器,挂公开面等于开流量自助机):`GET /ping`(极小响应,测 RTT)、`GET /download`(随机字节流式下发)、`POST /upload`(读丢弃计数)、`POST|GET|DELETE /results`(落库/历史/删除)。
- 发流必须不可压缩(crypto 随机块,块长远超 DEFLATE 32KB 滑窗)+ `Cache-Control: no-store, no-transform`,否则经 Caddy gzip/节点压缩字节数虚高。
- 全局 30s 读写超时(main.go)不动:下行时长默认 10s、钳制 [1s, 25s];上行由客户端到点停流(EOF),服务端只计数。单次请求必在 30s 内结束。
- 测速流量必须原生 fetch:下行 `ReadableStream` 按到达节奏累计字节;上行流式 POST(`duplex: 'half'`,不支持请求流的浏览器退化定量 Blob 计时)。axios(30s timeout 且不可流式读)只用于结果落库/历史查询。

## 测量口径

- **空闲延迟**:一串小请求 RTT 的**最小值**(排掉排队/调度噪声)。
- **抖动**:相邻 RTT 差值绝对值的**均值**。
- **下行/上行 Mbps**:流式累计字节 / 全程耗时,1 Mbps = 1e6 bit/s(与体检口径一致)。
- 落库数值统一前端 `round2`;后端只校验非负有限,`node_key` 空 = 直连/未标注(落 NULL,独立修剪桶),每 key 保留最近 50 条。

## "减法"模型(节点开销显式化)

历史按标注(节点 key 或直连)聚合成行,每行自动附与**直连基线**的差值:

```
节点开销 = 经节点实测 - 直连实测
```

聚合口径为桶内均值;直连行固定最前,其余按最近实测倒序。无直连基线时差值为 null(UI 占位,不编造 0)。文案纪律:"直连基线"勿简写为"基准"——撞 CONTEXT.md「基准行」(体检打 Cloudflare 的对照行),两个概念。

**孤儿历史**:标注节点已不在池(被清空/刷新冲回)的记录标"已失效",保留不级联删;孤儿语义由记录 key 对当前池快照派生(展示态,不入库),节点回池后"已失效"自动消失。

## 前端组织

`web/src/views/speedtest/`(目录制):`runner.ts` 测量原语(fetch 流式)、`utils.ts` 聚合/差值纯函数(独立单测)、`composables/`(运行状态机 / 历史 / 标注下拉)、`components/`(大数字结果卡 / 历史聚合表)。入口三处:主导航(路由 meta 注册)、节点表行内测试下拉"本机实测"、节点详情抽屉按钮——后两者带 `?node_key=` 直达预填(学 `/jobs?id=` 模式);预填 key 已不在池时提示并回落直连。

## 已知边界

- 经节点实测须用非 loopback 地址访问管理面(否则流量不绕行节点);会话 cookie 是 host-only + SameSite=Strict,换地址需重新登录(已拍板接受;生产 Caddy 域名部署天然消解)。
- 不做 loaded latency(下载打满时的延迟);实测结果不参与节点筛选/标签派生(单设备验收数据)。
- 测速下行打满宿主机网卡上行,与订阅下发、服务端体检基准行拉流共享管道,无 QoS:测速时订阅拉取变慢/体检数字失真是明知行为(单用户场景可控)。
